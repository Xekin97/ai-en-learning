# M003-UI-15 响应式与可访问性

## 视口与布局

| 范围 | 正式设计规则 |
|---|---|
| ≥1101px / 1440 基准 | 保持现有 192px 管理导航和主列。PAGE-501/502 操作位于页头右侧；PAGE-503/504 位于成长 panel 标题右侧。modal 最大 680px。 |
| 761～1100px | 导航收窄到 160px；页头操作可换行。页面数据和 modal 信息顺序不变。 |
| ≤760px | 管理导航改为横向滚动；页头动作换到标题下方且均分可用宽度。表格保持语义表格并在 `.table-wrap` 水平滚动。modal 从底部占据视口，body 独立纵向滚动，footer 固定。 |
| 390px 基准 | 容器左右 12px；modal 左右 8px、最大高度为视口减 16px；计数卡两列，确认页窄屏单列；footer 按钮至少 48px 高且无需页面滚动即可到达。 |

移动端不把完整 preview 压成摘要，也不省略配置项明细、移出项、可选字段应用结果、影响、字段或依赖。长类别/配置名和安全身份使用 `overflow-wrap:anywhere`；错误列表可换行，不造成整页横向滚动。

## 键盘与焦点

1. 导入/导出使用原生 button；文件选择使用原生 file input 的工程实现，设计演示按钮仅代替确定性文件结果。
2. modal 使用 `role=dialog aria-modal=true` 和标题关联；打开聚焦首个操作，Tab 循环，关闭回到原入口。
3. Escape/背景点击只在提交前安全状态关闭。`reading/submitting` 拦截 Escape；不能让关闭动作暗示已取消服务器提交。
4. 依赖和字段错误摘要链接到相应列表项/字段；焦点移动后保留清晰 `:focus-visible`。
5. 文件或类别变化后，旧确认 checkbox 清除；重新预览完成时焦点到 preview 标题或状态摘要。未知结果查询后焦点到新终态标题。

## 屏幕阅读器与动态状态

- 所有图标 `aria-hidden=true`；按钮可访问名称使用可见文案。类别入口所属标题/section 提供上下文，不用“导入”一词独立猜范围。
- `reading/submitting` 使用 `role=status aria-live=polite`；校验、依赖、口令和目标冲突使用 `role=alert`。计数容器有包含四项的可访问摘要。
- 密钥/口令错误只播报安全连接名和业务原因，不播报值、掩码或原始文件片段。
- disabled 与 loading 不只靠颜色；有禁用属性、文字状态和 spinner/图标。成功、错误和未知结果都有明确标题与正文。

## 触控与滚动

- 页面和 modal 关键动作至少 44×44px；移动 footer 按钮至少 48px 高。checkbox 的可点击 label 大于 44px，不缩小目标以适应长文案。
- modal body 和页面表格是独立滚动区域；footer 不遮挡最后一个可操作项，body 底部必须留足滚动空间。iOS 安全区用 `env(safe-area-inset-bottom)`。
- 正式 390px 配置项明细复验中，滚动到确认正文底部后 footer 底边 `835px < 844px`，两按钮高 `70px`，整页横向溢出 `0`；移出项保持完整可读。

## 语言和 reduced motion

中文和英文都使用同一 DOM 顺序；日期必须完整本地化，英文显示 `(Beijing time)`，中文显示“（北京时间）”。`lang` 随界面切换；配置名/模型标识保留源语言。

减少动效时停用 modal 位移与 spinner 旋转，状态文字仍可辨识；不会跳过校验、确认或等待时序。
