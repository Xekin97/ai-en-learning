# 模型推理配置调研

建议在管理台的**每个模型**下增加推理设置。服务商连接继续保存地址、协议和凭据；推理开关与强度属于模型配置。首版配置覆盖该模型的整个生成流程，不先增加六套分阶段参数。以下是调研建议，未修改产品合同、正式设计、运行参数或生成代码。

## 本次故障与实测

原请求选词为 `machine / preclude / interim / juvenile / retroactive`，游客、中文释义、故事、短篇。后端在约 2.5 秒拿到上游响应头，在规划阶段达到 180 秒调用期限；没有公开 plan item，未进入正文生成，额度已退回。只有一次上游调用，没有进入审稿或修稿。原请求费用、token 数未收到，查询该次供应商统计返回 404，因此保留未知。

使用当前代码导出的同一规划请求进行了三次限时诊断，仅保留推理长度和时间等统计，不保存推理文本：

| 请求 | 首个正式内容 | 结束/中止 | 实际结果 |
| --- | --- | --- | --- |
| 原 UAT 请求：服务商默认推理、prompt 输出 | 未产生可展示项 | 180 秒超时 | 生成失败 |
| 对照：相同默认配置 | 45 秒内没有 | 45 秒主动中止 | 持续收到推理，累计 19,840 字符；正式内容为零 |
| 对照：关闭推理、仍为 prompt 输出 | 3.338 秒 | 10.057 秒 | 收到完整输出，但带 Markdown 围栏，不是合格 JSON；不能记为生成成功 |
| 探索：low 推理、JSON Schema 输出 | 45 秒内没有 | 45 秒主动中止 | 正式内容为零；结构符合性尚无法评价 |

单次样本不能推导平均耗时或内容质量。最后一组同时改变了强度和输出模式，不是只改变强度的严格对照。原请求未捕获推理统计，默认配置的重放强烈支持“模型持续推理而未输出业务内容”这一原因，但不能还原原请求的全部上游行为。

证据：[原请求](evidence/uat-real-timeout-001/original-failure.json)、[默认配置重放](evidence/uat-real-timeout-001/saved-default.json)、[关闭推理](evidence/uat-real-timeout-001/reasoning-disabled.json)、[low 与结构化输出](evidence/uat-real-timeout-001/reasoning-low-structured.json)。三次是规划调用，不是三篇完整短文。关闭推理那次报告了 595 个输出 token、0 个推理 token；其余中止请求费用未知，不合计为零。

此前的“连接测试通过”仅指短流式问候可用，不能证明规划、正文、格式修正与付费审校的完整可用性。当前 UAT 仍有该问题，尚未修复。

## 已核实的能力和边界

2026-10-12 读取 OpenRouter 模型目录的结果：

| 模型 | 默认推理 | 默认强度 | 能否关闭 | 可选强度 |
| --- | --- | --- | --- | --- |
| DeepSeek V4 Flash 0731 | 开启 | high | 可以 | low / high / max |
| GLM 5.3 Flash | 开启 | max | 不可关闭（mandatory） | low / high / max |

这是读取时的能力快照，后续以目录及实际测试为准。不能因两者都支持 OpenAI Chat 协议就假定相同参数有效。[模型目录 API](https://openrouter.ai/api/v1/models)、[本地快照](evidence/uat-real-timeout-001/model-configuration.json)

OpenRouter 官方提供模型级能力信息，可据此限制开关、强度和预算选项。隐藏推理输出仍会执行推理并计费；总输出额度通常同时包含推理和可见内容，不能把缩小总额度当成可靠的加速方法。[官方推理说明](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)

结构化输出需检查实际路由端点支持情况，并使用要求参数支持的路由约束；最终仍要做应用校验，不能把 API 接受 schema 当成质量保证。[官方结构化输出说明](https://openrouter.ai/docs/guides/features/structured-outputs)

## 管理台建议

沿用 PAGE208 的服务商分组、模型卡片和“高级配置”，由正式设计在 M002 视觉基础上接入，研究文档不代替原型与设计交付。

| 配置/展示 | 建议交互 | 约束 |
| --- | --- | --- |
| 推理模式 | 跟随服务商 / 关闭 / 开启 | 默认保留“跟随服务商”；强制推理模型不能选择关闭 |
| 推理强度 | 开启时按能力展示 | 只列该模型支持的值；没有档位能力就不展示强度选择 |
| 当前默认值 | 只读提示，例如“服务商当前默认：开启，高” | 区分用户明确保存的值与可能变化的服务商默认值 |
| 能力状态 | 已识别 / 未识别，支持刷新 | 目录读取失败不能直接推断“无推理能力” |
| 结构化输出 | 保留现有开关 | 与推理设置独立；按端点能力验证 |
| 最大输出 token | 保留现有字段，说明可能含推理消耗 | 不新增一套重复的正文限额 |

推理 token 预算暂不作为首版必填项。后续确有支持该参数的模型接入需求时，再条件展示，明确它与总输出额度的关系。DeepSeek 与 GLM 本次元数据未声明 token-budget 控制，不为它们凭空提供预算输入。

“跟随服务商”不发送推理覆盖参数。“关闭”对已识别的 OpenRouter 适配为 `reasoning.enabled=false`。“开启”适配启用参数，若管理员选定强度则同时传支持的 effort；开启且未选强度时，不承诺具体档位。前端展示的默认建议只有经保存才成为显式覆盖。

能力来源属于服务商适配，协议属于传输格式。首轮建议验证 OpenRouter Chat 适配；其他兼容服务维持原请求行为。未经核实的服务商不照搬 OpenRouter 参数，也不静默忽略用户要求的覆盖。后续原生 Responses、Anthropic 或 DeepSeek 直连接入需要分别核验并测试其参数映射。

## 对生成流程的影响

- 关闭模型推理，仍执行现有“词义/用法/场景规划 → 正文”任务。它只影响模型内部计算方式，不删除规划步骤，不取消付费审稿和返修，也不改变两类返修上限。
- 推理配置在请求受理时与模型连接一起固定。随后规划、正文、技术修正、固定编辑、审稿和内容返修都使用同一配置快照；管理员中途保存只影响新请求。
- 首版采用模型级统一设置，便于验证、解释及回滚。分阶段覆盖留待证据表明“规划关闭、编辑开启”等组合能稳定改善速度与质量后再设计；当前没有这样的质量证据。
- 继续只向用户展示已生成的词义、用法、场景及正文。模型推理文本不能充当这些业务内容；后台可记录收到推理事件的时间与计数帮助排障。
- 增加“首个可展示内容”的计时，不把上游响应头、心跳或推理事件当作用户已看到内容。无内容等待的提醒和超时归因交给产品与后端设计，保留整体任务期限和取消机制，不以无限延长 180 秒掩盖问题。

## 接入与成本建议

现有修改入口：

- `backend/internal/admin/model_connections.go`、服务商批量保存逻辑及 HTTP DTO：新增配置验证、保存与返回，保留 CAS/原子保存。
- `backend/internal/ai/connections.go`：扩展模型快照；`gateway.go`：按服务商能力序列化。当前两处都没有推理配置。
- `frontend/app/pages/admin/models.vue`、`application/admin/model-draft.ts`、HTTP mapper/schema：增加条件控件及单模型测试参数，保留当前三协议的既有字段行为。
- 模型配置存储：由后端/DBA补充初始化定义。项目未上线，不安排历史数据迁移；不重置当前 UAT 数据。

能力目录只在管理台读取/刷新并短时缓存，不放进每次生成的关键路径。保存参数不调用付费模型。增加几个请求字段与少量耗时统计，不需要消息队列、新后台常驻任务或独立监控服务；供应商等待时间的下降是否带来容量改善，需要上线后依据实际占用统计。

复用现有调用记录，优先补首内容耗时、阶段总耗时、有效推理配置、可选的上游推理 token 数；没有上报的值保留 unknown，不存推理正文。此次失败已有 request ID、阶段、调用次数与额度退回事实，可继续使用。

## 验证及推荐落地顺序

1. 产品确认 PAGE208 字段和能力未知时的交互；后端明确模型配置、适配、快照与错误映射；正式设计按 M002 接入，不跳过设计直接改页面。
2. 实现模型级设置，保留服务商默认选项；受控测试验证 mandatory、支持档位、不同协议、批量保存与请求快照。
3. 连接测试继续明确只检测连接。另复用已有后台预览执行一次完整业务流程，核对首个词义/场景时间、最终有效稿和实际费用；需要测试开启审校时再用对应套餐，不以短“OK”代替。
4. DeepSeek 的优先候选是“关闭推理 + 已验证支持的结构化输出路由”；先用此次失败的同一组词测试完整中文流程，再对照内容质量，尚不能标记为修复。
5. GLM 的候选是其支持的较低档位，但本次未测试该模型的业务速度，不承诺换 GLM 即可解决。

本轮交付为调研与真实 UAT 问题记录；未自动调整模型配置，未增加真实模型批量测试，未宣布用户验收或里程碑完成。
