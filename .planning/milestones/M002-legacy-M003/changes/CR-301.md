# 补齐 pending 的显式重新核对动作

## 发现的问题

BE02 要求有限状态核对仍未收敛时，提供显式“重新核对”动作。UI02 的 pending 原型仅有标题和说明，`copy.json` 无对应独立动作键，前端无法直接复用批准文案及定位实现该既定行为。

## 证据与来源

- [API-302：故障、核对与权限](../technical/api/generation.md)：立即查询一次，最多每2秒、总10秒；未收敛提供显式“重新核对”，不无限轮询。
- [API-304：预览流、终态与核对](../technical/api/presets.md)：后台预览沿 API-302 的有限核对规则，使用独立 preview 身份和 token。
- [UI02 原型](../design/prototype/app.js)：`createPage()` 的 `pending` 分支没有操作按钮；[文案源](../design/copy.json) 没有重新核对动作键。
- 关联：PAGE-204/216、PAGE-212；UIA-M003-308；CAP-302/304；AC-308/313。前端角色已读取上述原件，仅登记缺口，未修改设计源或业务代码。

## 建议变更

- **CONFIRMED 既有范围**：核对现有请求的数据库状态；不是新生成、流式续传或重新扣次。来源为已接收 BE02 及本次责任回溯指令，无新增用户业务选择。
- **PROPOSED 最小设计补齐**：在 `copy.json` 增加 `action.recheck.zh`（“重新核对”）与 `action.recheck.en`（“Check again”），由 designer-tony 定稿准确文本；在 `#generation-status` 的 pending 说明之后定义对应按钮定位（建议 `#generation-recheck`）。后台预览 pending 复用该动作文本，明确其作用为当前 preview 的 status 核对并给出局部定位。
- 在当前设计规格/交互正文说明：自动核对窗口结束仍未确认时显示该动作；核对进行中禁用重复点击；仍 active 或暂时无法确认时保持 pending，不开放保存/发布，不宣成功。继续复用现有 pending 标题与说明，不建立新的错误文案体系。
- 仅核对已存在 run/preview、原 owner/token/TTL 范围；不持久化 token，不增加全页刷新恢复、后台续跑、模型调用或循环重试平台。

## 不变更的影响

前端只能自行创作文案和交互，或遗漏 BE02 要求的显式恢复入口。受影响的是 pending 的动作还原及相关验收，不影响已明确的 0–99 配置、双预算、最后有效稿、计次或预设发布业务规则。

## 路由建议

- 返回 `uiux-design / uiux/base / designer-tony`，仅补齐上述文案、局部原型入口及相应规格/交互和必要定向证据。
- `BLOCKED`：前端 pending 动作的准确文案/定位与最终架构交付；两份前端原件尚未落盘，按主线程指令暂停写入，待正式恢复。
- 解除条件：责任角色交付可定位、可复用且与 API-302/304 一致的显式核对动作，并由控制角色接回前端。无需用户重复决定业务语义。
- 本记录不修改 workflow、不切阶段、不启动实现；控制角色负责正式回溯。
