# 前端接收补充：成就说明、成长表单保存与管理员生成选项

## 发现的问题与证据

本条接收 PRODUCT-03 / UI22-H01 / DB-02 / BE-02。既有批准保持，下面是前端逐字段和操作边界核对发现的遗漏，不是要求用户重新决定产品范围。

| ID | 已批准的来源 | 当前技术缺口与影响 |
|---|---|---|
| FE2-G01 | [CAP-217 / D2-54 / AC-217](../product/abilities.md#cap-217)、[PAGE-210/214](../product/pages/index.md)；[operations.js](../design/prototype/operations.js) `content` 编辑 title/description/honor 三组双语字段；[growth.js](../design/prototype/growth.js) `achievement` 渲染 `.achievement-description`；copy.json `a.tier.description.zh/en` | [DB-02 §6](../technical/database.md) achievement_tiers 只有 name/title，无 description；[API-206](../technical/api/administration.md) 还明确写“不新增成就独立说明字段（DB无此列）”；API-203 Achievement 同样缺描述。不能持久化或显示已批准的成就说明，也不能把说明冒充称号/固定文案。 |
| FE2-G02 | [UI22 operations.js](../design/prototype/operations.js) `body/capture/handle(settings-save)`：签到页一次保存包含正常签到四值及首次掌握经验；等级/成就表格允许修改多档并一次保存；[AC-217](../product/abilities.md#cap-217) 要求失败不产生部分修改；每档内容弹窗修改属于表格编辑上下文 | API-206 将 mastery/checkin 分成两个 PUT，等级/成就每档分别 POST/PUT，且共用 expected_revision。前端串行逐行调用可能前几行成功、后几行失败；Promise.all 会产生 revision 冲突。接口没有明确一次“保存”的原子边界、整表门槛校验及逐行错误定位。不能自行增加端点，或改成每行单独保存来规避已批准交互。 |
| FE2-G03 | [API-202 §5](../technical/api/generation-presets.md#5-管理员预览边界)、PAGE-212：管理员使用全部已支持配置，不受访客词数/额度限制 | GET /admin/generation-options 仅有“返回所有平台支持枚举、完整启用模型安全引用及词表版本”的文字，没有完整成功对象/字段名、空值和缺凭据可用性结构。无法建立严格 schema 和契约 mock；不应猜它等同普通 generation-options 或从原型 fixture 发明字段。 |

浏览器接收见 [FE-01 原型结果](../technical/evidence/M002-FE-01-prototype.json)：growth 的中英文真实 DOM 都存在成就说明。该证据证明界面来源，不证明服务端功能已实现。

## 建议变更

1. **FE2-G01 / DBA 先接收**：给成就档位补双语说明存储、空值/缺译回退及迁移规则；现有名称与达成时称号快照各自保持。后端同步管理写读及学习者描述投影。说明是否可空须依据现有表单（只有名称必填，说明未设必填）明确为契约，不能新增说明必填门槛。这是建议字段语义，前端不把尚未批准的 DTO 写成既定接口。
2. **FE2-G02 / 后端接收**：为一次保存定义明确的事务命令。建议签到与首次掌握经验统一保存，内部仍保持签到下一学习日生效、掌握经验按已批准时效；等级/同类成就多档修改以变化集一次校验及提交，稳定档 ID 保持，支持新增档。整体失败不部分落库；返回当前完整投影、新 revision 和可定位字段错误。可以由后端提出其他等价的原子方案，但不能用客户端补偿回滚或逐行成功提示替代。DBA 确认锁序和事务即可，不必新增任意配置 JSON 或通用批处理平台。
3. **FE2-G03 / 后端接收**：补齐已有管理员选项 GET 的严格 DTO、未配置密钥/无模型/读取失败分支；保持无业务额度、只选支持的枚举、后台预览单独计量，禁止客户端自建枚举及供应商参数。

不新增任务体系、奖励类别、基础计划档位或新运营能力；不改 UI22。旧 BE/DB 冻结包保留，新版明确受影响章节及验证项。

## 不变更的影响

成长运营和成就展示无法按批准设计完整实现；多档保存可能半成功；预设后台类型和 mock 无法与服务一致。相关前端方案只提供组件/意图边界，不伪造可执行 DTO。不能据静态覆盖完整宣称整个技术阶段可进入实现。
