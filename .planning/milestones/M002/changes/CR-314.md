# 发音入口收敛及控件内状态

## 发现的问题与来源

用户明确要求：“选词位置不用播放功能，播放功能尽量集中，不要把状态渲染放到其他地方”。随后选择“每个单词一个紧凑控件，状态就地显示”。[原话及问答](../reviews/evidence/pronunciation-revision-132-r1/clarification.json)，决定号 `USER-M002-PRONUNCIATION-COMPACT-20261016`。

已接受 [M002-PRODUCT-08](../product/pronunciation/overview.md) 的 S402、PAGE-401 与 AC-401/408 含选词入口；旧待审 M002-UI-32（原 M003-UI-14）还含释义下独立状态卡和移动贴底口音菜单。这些条款与最新确认冲突，在本次发音范围内由本 CR 覆盖；旧产品/设计/证据不改写。

## 已确认变更

- PAGE-401 搜索候选、已选词都不提供发音，也不显示发音状态。保留选词、添加、移除的既有语义。
- PAGE-402 计划/结果词义、PAGE-403 已保存文章的每词详情各保留一个紧凑控件。加载、播放、完成、失败、重试、再次手势、口音替代均原位呈现。
- 禁止在释义下方、选词区、页面横幅或独立播放器渲染播放状态。口音菜单也就近锚定该控件。
- DATA-401～404、CAP-401～404 的目标词/来源/口音/单一活动播放语义继续有效；所有用户免费、不扣造文额度、不调用模型。产品中“同词再次点击从头播放”在本设计中按原义执行。
- 最新补充：用户要求“不用显示任何操作文本和状态文本……只有单个音源情况下不显示来源文本”，见 [原话](../reviews/evidence/pronunciation-revision-132-r2/clarification.json)，`USER-M002-PRONUNCIATION-ICON-20261016`。UI32-R1 的可见操作/状态文案与单音源来源文案退出标准。
- 单个可选音源只有播放/状态图标；多个可选音源才保留当前音源/口音名称和选择菜单。词典优先、浏览器兜底是技术路径，不因此额外算两个可选音源。无可见操作/状态文字或 hover 文案；无障碍名称和非可见读屏播报保留。
- 正确例：wander 加载时原图标转圈，失败时原位显示重试箭头；没有“准备中”“重试”“词典”等文字。错误例：图标旁再加状态行，或单音源也显示“英语”。
- 所选口音不可用时，原位警示图标点击打开既有选择菜单，由用户明确选择另一个音源；不在无文字按钮下隐藏自动切换含义。

- 尺寸修订：用户要求“还是太大了，去掉边框和边距”，见 [原话](../reviews/evidence/pronunciation-revision-132-r3/clarification.json)。移除常驻边框、底色、阴影和内外边距；18px 图标按自身尺寸布局，多音源名称紧凑跟随。不再用 R2 的 44px/66px 固定可见块。透明点击范围不占排版空间、不画边框；多音源相邻点击区不重叠。

## 影响与路由

设计角色在当前 uiux-design 内同步改原型、正式稿、文案、样式、交互及交接；无需重复确认已明确的范围。后续技术/前端/QA 用本 CR 读取被覆盖的 PAGE-401、AC-401/408 和 UIA-M003-439。

当前未开始发音技术和产品实现，不修改已验收的 CR313/UAT、真实模型配置或数据库。OPEN-401～403 的来源许可、真实环境和浏览器技术验证保持开放。
