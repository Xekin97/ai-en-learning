# 补齐管理员选词的词库搜索权限契约

## 问题与证据

已批准 UI26 的 UIA-PAGE-212-WORDS26 要求管理员在预设配置中搜索词库候选。提出缺口时，[API-004](../technical/api/generation-presets.md#1-选词随机候选及普通选项) 的 `GET /api/v1/vocabulary/search` 仅标注 V/L；API-202 管理选项返回 vocabulary_version，但没有另一条管理员词库搜索契约。前端不能把公开词库 API 的权限自行解释为包含管理员。

代码存在更宽的实现：[server.go](../../../../backend/internal/httpapi/server.go:141) 注册该 GET，使用共同 resolveActor/analyticsBrowser 中间件，没有 requireLearner；[catalog_handlers.go](../../../../backend/internal/httpapi/catalog_handlers.go:13) 的处理不区分管理员、只校验查询与 limit。此为静态代码证据，不等于本轮管理员真实 HTTP 已验收。

## 最小建议与不变范围

用户已明确要求优化后台预设选词，并通过 [065](../reviews/design-acceptance-065.md) 接受 UI26。推荐由 backend-alex 明确现有只读词库搜索对 V/L/A 的使用范围，保持查询参数、前缀优先、10/20 结果限制、现有返回 `{items:[{entry}],vocabulary_version}` 和错误结构。不要新增词条 ID、释义接口、全词表下载或第二套搜索端点来绕过文档缺口。

这不放开管理员的普通生成、随机选词或个人学习能力；后台仍只使用预设预览，且不使用学习者计划上限。无需新的产品选项；若后端判断存在不同权限需求，须先指出与批准设计的冲突。

## 路由与解除条件

- 同一 technical-design 阶段交 backend-alex 定向补齐契约与必要权限依据，再由 frontend-bob 接收。
- 局部阻塞 FE3-I04 的后台搜索真实接入及整体“全部接口已对齐”声明；普通选词、统一下拉、消息、释义、文案与首页方案可独立推进。
- 后端完成条件：正式文档明确管理员权限及无副作用边界；管理员请求成功/非法查询失败/无生成或额度调用的验证要求有定位，实际实现需要修复时说明范围。前端随后更新 FE3-G01 与追踪，不以当前代码现状静默代替契约。
- 本条已由 [066](../reviews/backend-cr027-entry-066.md) 登记到 open_change_requests，并在同一技术阶段激活 backend-alex；未批准 FE03/BE04 或切入实施。
