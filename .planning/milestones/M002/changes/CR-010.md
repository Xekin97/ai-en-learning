# 近30天分析图表撑宽页面，破坏窄屏布局

## 问题与批准来源

CAP219 / PAGE213、UIA-PAGE-213-01/COPY09、API209。UI22/H01 [design-spec详细规则](../design/design-spec.md#详细规则与实现自由)明确“页面不得整体溢出”；[响应式后台补充](../design/responsive-accessibility.md#后台补充)要求手机正文布局适配，允许表格在自身容器内横滚。当前实现将30个日点的图表最小宽度传播到整个页面，不属于允许的容器内滚动。

不是要求新增指标、改变查询口径或推翻设计。UI22原型以少量柱表示趋势，生产需承载既有7/30天真实日期数据；复制原样式不能替代动态数据适配。

## 复现与事实

frontend-cr009（276文件）/backend-cr007（285文件），真实生产前端、Go/PostgreSQL18、Chromium，管理员 `/admin/analytics`：

1. 390px或320px视口打开页面，默认近7天文档宽等于视口。
2. Period切换Last 30 learning days，三个真实分析API返回200，流量序列30个日点。
3. 390px和320px下，流量和转化面板均被撑到754px，document.scrollWidth=770；必须横向移动整个页面才能查看内容。
4. 桌面1280px对照：7天流量/转化列481/481，30天变766/200.8，转化文字被明显挤压。

[T15脚本](../verification/evidence/qa2-004/analytics-layout.mjs)、[全部几何与结果](../verification/evidence/qa2-004/analytics-layout-results.json)、[390px截图](../verification/evidence/qa2-004/T15-390-30.png)、[320px截图](../verification/evidence/qa2-004/T15-320-30.png)。三种视口分别重载后做7/30天对照，非仅凭截图猜测。T14数值/切换通过与本项布局失败分别保留。

定向定位：`frontend/app/pages/admin/analytics.vue`逐日渲染bar；`theme.css`中bar最小宽10px、gap14px，30点图表最小宽716px，`.split`为`1fr 1fr`，手机虽单列但轨道仍按最小内容扩展。该宽度与实测匹配。具体调整由前端角色选择，QA不改实现。

## 修复与复验边界

- 保持7/30学习日、真实API数值、无样本/观察中状态、30个日点与可读替代数据。
- 让动态趋势图适配所属面板，不把最小内容宽度传给页面；桌面流量/转化布局可读，手机无文档级横向溢出。
- 不以body overflow:hidden、删掉超出日点、缩短查询日期或隐藏转化面板代替修复。若图表内部需浏览/滚动，应保证内容及键盘可达，不能裁掉数据。
- 至少复验7/30天在320/390/1280/1440px，中英文长标签、空/观察状态，实际切换后 `document.scrollWidth <= innerWidth`；对应图表的可读标签/替代数据与API范围一致。共享样式修改时检查直接受影响的其他split/chart用途，不要求无关全量重跑。
