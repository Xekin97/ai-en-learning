# 分页模型目录使道具编辑遗漏或丢失已有模型引用

## 问题及批准来源

[CAP-217 / AC-217](../product/abilities.md#cap-217-成长运营与积分管理)、D2-41/51/74、[API-206 道具定义管理](../technical/api/administration.md)、UI22 PAGE-210 允许维护模型卡配置；修改成功须与用户可见配置一致，未要求移除的模型不能因选项分页被移除。已有下架引用可保留，但不能新引用下架模型。

CR008 修复了已加载目录中下架模型被过滤的问题。本轮原场景 S05–07 通过；目录超过 API 默认 20 条时，仍存在另一个独立的数据完整性缺陷。

## 复现与证据

使用 frontend-cr008 / backend-cr007 生产版本、真实 Go/PG、Chromium 后台：

1. 目录超过 20 个模型；创建卡，引用首屏模型 B 和后续页模型 X，之后正式下架 X。
2. 在 /admin/growth 编辑该卡。X 不在选项中，只有 B 显示选中。
3. 用真实 Meta+鼠标点击增选首屏模型 C，不执行取消 X；点击保存。
4. PUT 返回 200，请求与持久化集合变为 B、C，原 X 被删除。

[首次请求/数据库结果](../verification/evidence/qa2-003/S08-paginated-reference.json)、[实际鼠标重复复现](../verification/evidence/qa2-003/pagination-details.json)、[保存前截图](../verification/evidence/qa2-003/S08-modifier-click-before-save.png)、[复现脚本](../verification/evidence/qa2-003/pagination-repro.mjs)。S08 与 S08-repro 为同一问题的两次独立样本，不重复计缺陷。

同一根因的另一表现：只有 X 的卡进入编辑后没有选中项，仅把下架积分 20 改 35，required 多选框拦截，0 次 PUT，金额仍为 20。点击已有“加载更多”后 X 才出现并自动选中；再次保存成功，金额变 35。[S13 截图](../verification/evidence/qa2-003/S13-empty-selection.png)及 pagination-details 的 sole-reference 对照。可见模型目录分页被当成完整的编辑值集合。

定向定位：ItemDefinitions.vue 只从 admin.state.models 渲染 option；admin.loadModels 首次仅一页，api-repository.listModels 固定 limit=20。baseline 虽持有 X，未加载的目录没有 X 的 option；原生 change 通过 v-model 用当前 DOM 选中项替换 modelIds，丢失未显示的引用。这是前端读入/表单同步问题，不要求后端放宽新下架引用校验。

## 修复边界与复验

由 frontend-claire 确保编辑器完整呈现并保留已有引用，无论所在目录页。可选新模型继续分页；具体加载/选项合并方案由实现角色选择。不得靠取消 required、强制替换 X、允许新增下架引用或要求管理员猜测还应加载几页来规避。

复验至少覆盖：仅后续页旧引用时只改积分可提交；首屏与后续页混合引用时增选可见模型不丢旧引用；显式移除旧引用才改变集合；新卡仍不能选下架模型；分页加载失败与 revision 冲突保留原配置和输入，不提交未知缺失集合。保留 CR008 的同页改价→旧退款预览失效→新金额到账链路。

影响：管理员保存可能无提示地改变后续发放卡的模型集合；仅后续页引用的旧卡难以维护即时下架积分。按既有契约已发卡模型使用发放快照，此项不推断旧库存被改写。
