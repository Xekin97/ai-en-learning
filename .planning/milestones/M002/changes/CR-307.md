# 模型编辑模态框的键盘焦点会逃逸且保存后不回原按钮

## 发现的问题

独立 QA 在真实 Nuxt 页面、Chromium 与隔离正式后端中验证模型编辑 `AppDialog`。弹窗确实位于 top layer，遮罩、内部滚动、固定 header/footer 和脏数据确认也成立，但焦点合同有两个同源偏差：连续 Tab 遍历会离开最上层弹窗并落到页面 `BODY`；有效保存关闭弹窗后，焦点也落到 `BODY`，没有回到打开该弹窗的精确“编辑服务商”按钮。

桌面 1440×900 与移动 390×844 的结果一致。独立 QA 没有修改生产代码或放宽批准断言。

## 证据与来源

- 上游产物：[`design/interactions.md`](../../M002-legacy-M003/design/interactions.md) 模态框生命周期；[`design/responsive-accessibility.md`](../../M002-legacy-M003/design/responsive-accessibility.md) 键盘与焦点；[`design/design-spec.md`](../design/design-spec.md) `UIA-M003-416.r1`。
- 相关编号：AC-322、UIA-M003-416.r1、UI10-R1.1。
- 复现：管理员进入 `/admin/models`，打开任一现有服务商编辑框，展开模型高级设置并聚焦自定义参数 textarea；连续按 Tab，第 14 次后 `document.activeElement` 为 `BODY` 且不在 `#admin-model`。重新打开并保存有效 JSON 后，弹窗关闭，`document.activeElement` 仍为 `BODY`，原编辑按钮未恢复焦点。
- 结构化原件：[`verification/evidence/cr306-qa/browser.json`](../../M002-legacy-M003/verification/evidence/cr306-qa/browser.json)。其中 desktop/mobile 的 `firstFocusEscape` 均为 `iteration:14, tag:BODY`，`focusStateAfterSave.tag` 均为 `BODY`。
- 代表截图：[`desktop-model-dialog.png`](../../M002-legacy-M003/verification/evidence/cr306-qa/desktop-model-dialog.png)、[`desktop-discard-confirm.png`](../../M002-legacy-M003/verification/evidence/cr306-qa/desktop-discard-confirm.png)、[`mobile-invalid-json.png`](../../M002-legacy-M003/verification/evidence/cr306-qa/mobile-invalid-json.png)。截图用于环境与布局旁证，焦点结论来自实际 DOM。

同批检查中 top-layer/遮罩、错误原文保留与错误字段聚焦、迟到 probe 失效、取消/Escape/header/backdrop 四入口脏确认、固定 header/footer、无横向溢出、移动端 44px 目标、保存重读与保存零 provider 调用均通过，因此本请求只处理焦点生命周期。

## 建议变更

- 用户已明确的要求及确认来源：沿用 UI10-R1.1 已批准的真实 `showModal()`、最上层焦点约束，以及父框关闭后回精确 opener；根代理已将本缺陷分配为 CR-307，并授权按既有合同修复，无需新增产品或视觉决定。
- 为 `AppDialog` 补足 Tab/Shift+Tab 循环约束；存在叠层确认时只约束当前最上层，关闭确认后回父框的实际触发点。
- 保存导致列表重取/重渲染时，仍用稳定身份找到并聚焦原服务商的编辑按钮；取消或放弃关闭保持同一合同。
- 不改变 JSON 校验、保存、probe、后端 API、视觉或内容生成行为。

## 不变更的影响

键盘用户可从模态任务逃逸到被遮罩的底页，且保存后失去上下文，AC-322 的窄屏/键盘可操作与 UIA-M003-416.r1 不能通过独立验收。
