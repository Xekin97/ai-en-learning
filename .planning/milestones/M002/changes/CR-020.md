# 头像下拉菜单未完整处理关闭与焦点

## 发现的问题与批准来源

UI22 [交互规范“全局导航与个人中心”](../design/interactions.md#全局导航与个人中心--page-205206214215217)明确要求：“Escape 关闭并回头像；点击外部或焦点离开关闭”，以及“选择后关闭下拉并将焦点移到右侧页标题”。关联 CAP-209 / D2-77、PAGE-205/206/214/215 的 NAV11；本次直接覆盖首页与个人信息入口。

当前生产构建在中英文、320 WebKit / 1440 Chromium 均出现同一组偏差：

| 操作 | 期望 | 生产实际 |
|---|---|---|
| 展开后点击外部 | 关闭菜单 | 仍展开 |
| 从菜单最后一项移出键盘焦点 | 关闭菜单 | 焦点已离开，菜单仍展开 |
| 菜单链接获焦后按 Escape | 关闭，焦点回头像 summary | 已关闭，焦点落到 BODY |
| 选择“个人信息” | 进入页面、关闭菜单、聚焦右侧标题 | 路由和关闭正常，焦点落到 BODY |

Enter/Space 展开、四项文案和顺序、选择后 aria-current 及路由均正常；这是一个共享菜单的交互闭环问题，不拆成多个 CR。它会干扰键盘用户连续操作和当前位置判断，未发现数据或权限损坏。

## 复现与证据

1. 合成学习者登录后在首页展开头像菜单。
2. 在首个菜单链接上按 Escape；检查焦点。
3. 再展开，分别点击菜单外部、从末项移出焦点；检查 details.open。
4. 再展开并选择个人信息；检查路由、菜单状态与 document.activeElement。

[有效判定及逐项结果来源](../verification/evidence/qa2-017/assessment.json)：N17-en/zh-1440 使用根 results，N17-en/zh-320 使用 keyboard-control/results。每项与相同语言/视口的已批准原型执行相同步骤；原型四项全部满足，生产四项全部失败。桌面普通 Tab，Mac WebKit 使用 Alt+Tab 访问链接，双方同条件。

[控制结果](../verification/evidence/qa2-017/keyboard-control/results.json)保存外部点击命中元素、节点焦点与 open 状态；对应目录的 outside-3300/3332 截图保留。最初手机点击点被正常展开的菜单覆盖、原生 Tab 跳过双方链接等测试条件修正见 [corrections](../verification/evidence/qa2-017/corrections.json)，不据其另立产品缺陷。

实现定位：[AppHeader.vue](../../../../frontend/app/presentation/components/AppHeader.vue)的 details 仅设置 open=false，路由 watch 也仅关闭菜单；没有上述外部点击/焦点离开及返回头像/标题的完整处理。[输入与构建摘要](../verification/evidence/qa2-017/inputs.json)绑定 frontend-cr019，应用未改。

## 建议修正与验收边界

由 frontend-claire 补齐共享头像菜单四项现有交互：外部点击关闭、焦点移出关闭、Escape 返回触发头像、选择分区后聚焦右侧标题。保持四个既有入口、批准文案/图标、原生键盘展开、当前页标识和响应式布局；各分区使用同一焦点规则。参考批准原型已有 document click/focusin/keydown 与页面标题处理，不引入新菜单产品要求。

修复后按 N17 中英手机/桌面复验四项，并确认其他三个分区入口沿同一规则；首页与欢迎的已通过证据按实际改动接续，不要求重建测试平台或机械重跑整个里程碑。
