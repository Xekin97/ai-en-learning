# 已下架模型卡的后台编辑被空模型必选框阻断

## 发现的问题与批准来源

D2-51、CAP-215/217、API-204/206 与 UI22 PAGE-210 允许管理员修改已有模型卡的下架积分，并即时影响尚未退换的卡。CR-006 的后端保存缺陷已通过本轮 R09/R10，但实际后台页面仍无法完成此操作。

## 复现与证据

1. 创建仅包含一个可用模型的模型卡，下架积分为 20；正式移除该模型。
2. 打开 /admin/growth → 道具配置 → 编辑该卡，将下架积分改为 35，其余字段不变。
3. 点击保存。AI model 多选框没有任何选项，却设置 required；浏览器提示 Please select an item in the list.。
4. 实际发出 PUT 数量为 0；GET 定义仍为 20，model_ids 未变。

[实际页面截图](../verification/evidence/qa2-002/admin-retired-card-ui.png)、[DOM 与请求记录](../verification/evidence/qa2-002/admin-retired-card-ui.json)、[R08 脚本](../verification/evidence/qa2-002/cards-reverify.mjs)、[结果](../verification/evidence/qa2-002/cards-audit.json)。

定向定位 frontend/app/presentation/components/admin/ItemDefinitions.vue：编辑器对模型选项统一 filter(!retiredAt)，但 select 仍为 multiple required。已保留在 draft.modelIds 中的下架 ID 没有对应选项，原生校验在提交处理之前就阻断保存。UI22 原型 app.js 的 itemForm 与既有下架退款规则作为来源，不据此引入新字段或业务流程。

## 建议变更与复验

由 frontend-claire 在现有编辑器中区分“保留已有下架引用”与“新增模型引用”：显示足够的已有模型信息并允许只改积分提交；不能要求管理员换成其他模型才能保存，不应通过取消全部模型校验让新卡接受无模型或下架新引用。维持后端 CR-006 的约束、revision、类型字段及真实成功/失败反馈。

独立复验须从真实后台页面完成改价，确认请求实际发出且刷新持久；用户新预览立即采用新金额，旧预览要求重新确认；再覆盖包含可用与下架模型的既有卡以及新建卡校验。仅调用 API 或契约 mock 的通过不足以关闭本项。

## 路由与影响

返回 implementation / frontend-claire，P2，本期道具运营与最终 UAT 阻塞。无新产品问题待用户决定；不修复则管理员无法兑现用户已确认的即时下架积分规则。

本项是前端浏览器校验遗漏，与 CR-006 的服务端 422 根因和责任不同；保留其 API 修复通过结论，不据此宣布端到端流程已闭环。

## 解决记录

QA03 / S05–07 及 S06-live 独立复验原缺陷通过：已有下架模型在已加载目录内显示并保持选中；后台页面 20→35 实际 PUT 200，刷新持久且引用不变；用户旧预览返回 409，点击重试看到 35 后再确认，仅退一次。混合已启用/已下架模型、320px、新卡排除下架及空选择拦截通过。见 [结果](../verification/evidence/qa2-003/cards-results.json)、[请求与退款](../verification/evidence/qa2-003/cards-details.json)、[启用模型补验](../verification/evidence/qa2-003/mixed-live-results.json)。

该结论限定于原“过滤已加载下架 option”缺陷。目录后续页的已有引用仍会遗漏/丢失，作为不同触发与根因的 [CR009 / QA2-F05](CR-009.md) 继续阻塞；不宣称模型卡全部编辑状态通过。CR008 判定 verified_pending_gate，正式关闭由守门登记。
