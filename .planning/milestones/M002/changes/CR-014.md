# 书架搜索、加载更多和参与切换后未恢复设计规定的焦点

## 依据与边界

UI22 [书架交互](../design/interactions.md#书架--ui-18)明确：搜索结果重绘后焦点回输入；加载更多后移到首个新增标题；参与切换重绘后回同一checkbox。[UI18验收](../design/design-spec.md#ui-18-书架)要求控件重绘不丢焦点。原型learning.js的search/clear/more也显式执行这些动作。关联CAP012/013/015、PAGE005、UIA-PAGE-005-01/02/LIBRARY18；这是批准交互的实现缺口，不是QA新增键盘规则。

## 复现与实际

frontend-cr012 / backend-cr013，真实生产前端、Go/PostgreSQL、本人21篇短文、查询LEARN：

| 动作 | 预期 | 实际 |
|---|---|---|
| 点击搜索并等200/20行结果 | 焦点回搜索输入 | 留在Search/搜索按钮 |
| 点击加载更多，20→21行 | 焦点移至首个新增标题 | 按钮消失后焦点落到BODY |
| 关闭某篇参与日期复习，等PATCH200/复选框重新可用 | 焦点留在同一复选框 | 焦点落到BODY |

J05/J06在中英×320/1440px均复现；[两个新浏览器上下文](../verification/evidence/qa2-007/independent-repro-v2.json)另用英文1440和中文320复现全部三种操作。等待请求和页面稳定后记录activeElement；不是截图推断。参与操作确实持久成功，统计不同步另记CR015。

原始[结果](../verification/evidence/qa2-007/library-results.json)、[脚本](../verification/evidence/qa2-007/library.mjs)、[独立复现](../verification/evidence/qa2-007/independent-repro-v2.mjs)、[搜索](../verification/evidence/qa2-007/v2-search-en.png)、[加载更多](../verification/evidence/qa2-007/v2-load-more-zh.png)。runtime为空，axe静态扫描通过不代表动态焦点符合设计。
