# 真实生成 Plan 与连续草稿缺少已批准书写点

## 发现的问题

独立 QA 在真实 Chromium、Nuxt、Go 与 PostgreSQL 栈中观察普通生成的 Plan 和连续草稿共存状态。两区均能持续显示且阅读列、焦点和终态清理正确，但批准设计规定的书写点完全未渲染：运行 DOM 中 `.m003-writing i` 数量为 0，页面截图也没有这一生成中状态提示。

这不是对原型 DOM 类名的机械要求。已批准交互将书写点定义为唯一新增循环动效，并明确要求 `prefers-reduced-motion: reduce` 时停止；生产主题也已经保留其样式和 reduced-motion 规则。缺失节点使正常模式没有该视觉状态提示，也使这一批准动效的减弱行为无法在真实 Plan/草稿上发生。

## 建议变更

- 用户已明确的要求及确认来源：复用 M003 已批准的三点书写状态；不新增动效或视觉规则。
- 在真实普通生成 Plan 与连续草稿的生成中 header 渲染批准书写点，保持 `aria-hidden=true`，并消费现有 reduced-motion 样式。
- 检查后台预览的对应生成中区域；若同一批准规则适用则一并补齐，避免两处行为分叉。
- 由 QA 定向复验可见节点、正常动效与 reduced-motion 停止；不要求生产 DOM 复刻原型其他类名或层级。

## 不变更的影响

用户在流式阶段看不到批准的持续写作提示，FE3-V11 的实际页面动效与 reduced-motion 合同不能完整成立。
