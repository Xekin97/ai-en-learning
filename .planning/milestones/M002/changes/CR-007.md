# 领取过游客短文的账号不能注销

## 发现的问题与批准来源

[CAP-005 / AC-005](../product/abilities.md#cap-005-注销账号并删除数据)、[API-003](../technical/api/identity-library.md)及 [DB2-T13](../technical/database.md)要求正确密码和明确确认后立即永久注销，清除 claim、学习与关联个人数据，失败不得部分删除。

访客生成短文后注册并领取到本人书架，使用正确密码注销返回 500 internal_error；删除事务回滚，账号、已消费 claim 与批次仍存在。无 claim 的新账号同接口返回 204，随后读取 401。

## 复现与定位

1. 在真实 Go/PG 隔离环境创建并发布预设；访客生成，注册学习者，正式 claim 入库。
2. 使用当前有效密码请求 DELETE /api/v1/me/account，body 含 current_password 与 confirmed:true。
3. 期望 204、注销所有会话且个人数据清除；实际 500。
4. 再登录重复同一请求仍 500；数据库已有 consumed claim 数量前后均为 1，批次 ID 集合未变。新注册无 claim 账号对照可注销。

[首次 R07](../verification/evidence/qa2-002/review-reverify.json)、[重复与对照](../verification/evidence/qa2-002/additional-audit.json)、[复现脚本](../verification/evidence/qa2-002/additional-audit.mjs)。脚本依赖 review-reverify 准备的合成账号；私有运行凭据不写入证据。

数据库报 visitor_claims_state_consistent：删除 account 触发 consumed_account_id 的 ON DELETE SET NULL，consumed 状态却要求该字段非空。backend/internal/identity/service.go 的 DeleteAccount 直接调用 DeleteAccount SQL，之前未清除此用户的消费 claim；定义见 backend/db/migrations/0002_core_tables.sql。此为定向原因，不宣称所有删除关联均已审查。

## 建议变更与复验

按已批准账号删除范围，在现有事务/锁语义内正确删除该账号关联 claim 与个人数据；保留错误密码和未确认保护、原子失败、其他用户及平台资源隔离。由后端实施决定最小实现，不放宽状态约束来保留失效私人关联；若确需契约/结构变更，回到对应责任角色评估。

复验覆盖已领取游客内容与纯注册账号；正确注销 204，多会话失效、账号不可登录、个人批次/成长/卡/可识别分析与 claim 不可恢复；错误密码/未确认不删除，其他用户及共享配置保留。既有 USER-CLAIM-DELETE-001 的单批删除行为仍需保留。

## 路由与影响

返回 implementation / backend-ethan，P2，本期账号与最终 UAT 阻塞。无新用户决策；不处理即保留常见试用转注册路径的注销失败。QA 不自行修改实现或迁移。
