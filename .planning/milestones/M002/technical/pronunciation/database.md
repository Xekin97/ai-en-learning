# 单词发音数据设计

建议复用页面已取得的单词，音源、设备声音和播放状态只在运行时使用。本增量不新增数据库表、字段、索引、永久播放记录或配置类别，不执行迁移。点击发音不进入造文、额度、学习结算或文章保存事务。

这是待审的数据边界方案，不代表发音已实现或技术阶段整体通过。后端仍须完成音源使用条件和请求路径设计，前端仍须完成设备能力与播放生命周期设计。

## 2. 数据模型与生命周期

下表定义逻辑数据含义，不规定 HTTP 字段、接口地址或前端组件实现。

| 数据资产 | 最小逻辑内容 | 所属边界 / 生命周期 | 持久化决定 |
| --- | --- | --- | --- |
| DATA-401 当前词 | 当前可见卡片的 `entry`；用于绑定回调的本地页面/控件身份 | 已有页面负责读取权限；点击后复制该词作为本次尝试的固定输入，不能从随后变化的卡片重新取词 | 既有词库、文章快照不变；不为发音另存一份词 |
| DATA-402 词典资源 | 本次匹配的音频定位信息、实际来源、已核实的口音与必要许可信息；缺失值保持未知 | 第三方数据可变、可失效；当前尝试或当前页面短暂使用，页面离开/上下文失效后释放应用持有的引用 | 首版无音频表、对象存储或应用主动持久缓存；资源使用/缓存许可由 OPEN-401 核实 |
| DATA-403 设备声音 | 当前环境提供的声音引用、语言/地区和可用性 | 浏览器实例有效；声音列表改变时重新判定。不能用另一设备的结果或上次账号的记录推断当前可用性 | 不写账号偏好、数据库、localStorage 或 IndexedDB；不序列化浏览器声音对象 |
| DATA-404 播放过程 | 当前目标、用户显式选择（如有）、实际使用的来源/口音、状态、尝试令牌和取消句柄 | 页面内单一播放协调；一个活动播放意图；结束/失败/取消后释放活动资源，控件可保留本页必要的终态用于重试 | 无播放历史、待播队列、额度账、复习记录、成长奖励或运营配置 |

`entry` 仅是查找/朗读内容，不是异步任务的唯一身份：相同单词重播、不同页面的同词、账号切换都必须区分。建议采用页面上下文代次和递增尝试令牌，作为 DATA-404 的内存实现细节，不新增持久任务 ID。

口音事实与用户选择必须分开：选定口音不可用时不得把回退声音标成原口音。未知地区不补造 UK/US。词典请求和浏览器兜底是处理路径，不自动等于两项用户可选音源；只有实际可选资源才产生菜单。单音源仍需要内部来源信息用于准确的无障碍描述，不能因界面隐藏来源文字而删掉这一事实。

UI 继续遵循 R3：18px 裸图标、无边框和内外边距，状态原位显示，无可见操作/状态文本，单音源无来源文本。DBA 不扩展显示字段或增加播放记录页面。

## 3. 存储、约束与成本取舍

| 方案 | 收益 | 代价 / 选择 |
| --- | --- | --- |
| 复用已有词 + 临时资源和状态 | 现有卡片数据足够；刷新后重新判断资源；没有账号同步、删除和数据维护负担 | **推荐首版**。重复播放可能重复访问音源，是否需要有界内存复用由后端/前端依据实测决定 |
| 持久保存每词音频 URL 或下载音频 | 可能减少部分重复请求，具备跨会话复用机会 | 需要处理失效、许可、刷新和存储成本；当前产品没有离线/音频收藏需求，不采用。后续出现明确需求再设计 |

**物理数据库增量：零。** 继续使用当前 PostgreSQL 和原数据模型；不增加表、字段、约束、索引、角色权限、种子数据、MQ、Redis 或数据库后台任务。

- 已有 `vocabulary_entries` 的词库快照/词条唯一性、`lexemes` 身份、`learning_batches` 所有者关系和 `batch_targets` 批次词唯一性保持原义；发音不参与词条规范化写入。
- 本功能直接使用页面已有 `entry`，不需要按音频 URL、播放次数或口音做 SQL 查询，因此没有新增索引访问路径，也不对已有详情查询做无关改造。
- **方案目标**为每次播放新增业务数据查询 0、写入 0；这不是现网测量值。页面原本的详情请求、通用会话处理仍有成本。若后端拟新增端点，其公共中间件成本应单独说明，不能把总服务开销宣称为零。
- 播放单次等待、资源大小、每秒请求量和并发尚未测量。本方案不承诺总体服务器零负担或特定容量；实际直连/代理路径、超时和成本核算属于 OPEN-402/后端方案。
- 若技术验证发现必须使用持久缓存，需先补充保留期、许可、访问路径及 DATA-402 的生命周期影响，再回到本数据方案修订；不能直接往已保存文章中加音频字段。

## 4. 一致性、并发和退出规则

DB401-C1：仅用户点击触发播放；卡片出现、流式更新、刷新和声音列表就绪均不自动发声。发音没有自己的数据库事务或行锁。词典请求、下载、浏览器等待和播放不得持有数据库连接或包在已有保存/认领/复习事务中；不复用造文任务注册器来创建发音任务。

DB401-C2：新的播放意图先使旧尝试令牌失效并请求取消旧工作。旧请求、媒体事件、语音结束/失败事件只有仍匹配当前上下文及尝试令牌时才允许更新控件；即使底层取消未及时完成，迟到响应也不得恢复旧播放或改变新目标。

DB401-C3：同词再次点击产生新的尝试，从头播放；单页面不建立队列。计划转结果、重新生成、词卡移除、文章删除/离开、组件卸载、会话失效/切换均需要核对目标是否仍属于当前可见上下文。目标失效就取消并清理；不得因 `entry` 恰好相同继承旧页面的播放。保留同一卡片时是否复用协调器由前端决定，但不得造成两个控件同时持有播放所有权。

DB401-C4：字典缺失/空资源/失败/超时可有限回退一次；浏览器仍不可用则到达可重试终态，不能无限准备或在两条路径间循环。若已进入浏览器兜底但需要再次手势，下一次点击直接尝试该兜底，不重新走已失败的词典路径。用户选择口音后，匹配口音不存在时应由原控件显式选择替代。确切超时和声音就绪规则交 OPEN-403；正式稿演示延时不是生产参数。

DB401-C5：播放成功/失败不影响生成内容有效性、保存结果、额度、复习成绩、成长奖励或最后学习时间。保存只接收原有学习数据；不能把音源字段合并进生成结果、事件快照或导入导出的配置包。

## 5. 权限、保留与运维

- 私人文章继续由已有详情读取检查所有者；发音消费已合法展示的词，不提供凭文章 ID 获得他人文章/目标词的捷径。免费使用不等于开放文章读取权限。
- 向发音适配器仅传当前英语词；外部请求不携带正文、释义、账号/访客 ID、文章 ID、造文令牌、学习历史或 API Key。实际请求携带的网络元信息、referer、跨域与音频 URL 校验由后端设计核实。浏览器声音对象不能被当成“必定离线”的证明。
- 不新增按用户、文章或单词聚合的播放分析记录。若接入现有运行日志/监控，仅记录去内容的结果类别、路径和耗时；不要把单词、音频 URL 或身份当高基数标签。是否需要这些观测及落点由实现职责决定，本方案不另建日志库/审计体系。
- 不做新数据迁移、历史回填、清库或 UAT 数据调整；现有迁移文件仅为只读证据。项目未上线的事实不构成删除已有开发数据的授权。
- 无新增持久数据，故无新增备份、恢复作业或音频备份。撤回发音实现时仅清理运行时资源，不需回滚数据库。既有文章备份/恢复和所有者删除语义保持；见[首次发布兼容政策](../../../M001/reviews/first-release-compatibility-policy.md)与[认领后删除规则](../../../M001/reviews/claimed-batch-delete-retention-exception.md)。
- 应用不主动持久化音频不等于控制浏览器 HTTP 缓存或第三方留存。OPEN-401/402 必须说明实际路径，不能承诺客户端外绝无保存。
