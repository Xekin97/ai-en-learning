# M002：继承一期的完整产品基线

## 当前版本与审阅入口

本稿为 **M002-PRODUCT-06**，按[CR029](../changes/CR-029.md)与[092](../reviews/model-generalization-092.md)将平台模型配置统一为服务商连接与模型注册。仅管理员配置，三种协议分别支持；参照用户提供的列表、表单、密钥与连接测试交互，OpenRouter一并纳入通用体系。旧M002功能和已关闭CR025–028完整继承；原消息一次提醒已确认按账号+消息在浏览器记录，不再是未决事项。

当前范围和验收见[CAP101/102](abilities.md#cap-101)、[数据资产](data-assets.md#data-007)、[PAGE208](pages/index.md#page-208)、[AI契约](ai-behavior.md)、[决定D2-90–92](../decisions/product-decisions.md#d2-90)。默认模型已明确不做，每次手动选择。当前无产品待决。

## 模型配置增量（CR029）

管理员从模型管理中添加通用模型，填写显示名称、原始模型ID、服务商连接、协议、Base URL和API Key。已有连接可显式复用；不同密钥不能覆盖他人共用连接。统一列表提供编辑、测试连接、启停、移除及相应结果反馈。服务端加密保存密钥，管理端仅见已配置状态。参考稿本机配置文件与个人最近模型列表不属于本Web产品。

保存与网络测试分离；只有管理员主动测试才访问上游。正常造文继续按身份和计划/卡片授权，预设沿锁定模型，模型接入不新增自由聊天或多模态生成。输出上限等高级参数仅在有实际配置时传送，不由名称猜测。既有OpenRouter模型迁入统一结构且保留身份、计划/卡片/预设关联及历史内容。

## 用户价值、角色与完整范围

以“选词—AI 英文短文—收录个人复习库—反复学习”为主路径，二期增强完整复习体验、低成本试用、可见成长及后台运营。界面更新不能取消一期功能，成长不能取代复习库，学习等级不能取代基础计划。

访客可造文或试用、浏览公开页面、注册和登录；学习者管理自己的账号、批次、复习与成长；管理员仅通过后台管理平台及明示用户操作。管理员预设预览是新增专用授权，不授予管理员代用户学习、复习或修改其内容。

首页保持简洁并增加紧凑优势介绍，Header 沿 UI22 已确认文案和顺序“首页、精选、学习、复习、书架”，不增加学习成长导航。头像四菜单为个人信息、账号成长、道具卡、兑换中心；四视图共用左侧个人基础信息与右侧具体内容。后台为概览、数据分析、模型管理、计划管理、用户管理、成长运营、首页预设、消息管理八个独立模块。

## 必须闭环的当前路径

1. **普通生成与收录**：Header 造文 → 精确选择固定词表词条（可随机加一个）→ Story/Brief 合法默认、显式选择模型/释义语言 → 预检与占额 → 流式 → 完整有效 → 收录或放弃 → 个人复习库找到完整批次。失败/取消按不同规则结算；无效结果不保存。
2. **访客认证**：有效结果点击收录 → 独立注册/登录（可互切且保留有效上下文）→ 角色分流和一次性收录 → 同学习日认领签到 → 欢迎/对应消息正文。失效不伪报成功；不再次调用或扣账号额度。普通受限入口认证后返回原意图。
3. **个人复习库**：六项全库统计 → 目标词条搜索 → 旧到新批次列表（当前标题及目标词条）→ 详情编辑标题并保存/取消、参与开关、单批直接复习、删除确认。暂不参加日期复习仍可单批复习；删除不回退累计成长，不能恢复内容。
4. **按日期复习**：本地日期默认最近 7 天 → 校验包含边界与参与批次命中数 → 固定随机批次/词序会话 → 当前批次作答 → 任意进入概览并改答 → 提交 → 临时正误对照 → 下一批/完成/整批重来。单批次会话与日期范围互不覆盖，已完成跳过；草稿恢复先确认。
5. **资料与账号安全**：头像个人信息 → 昵称/选填性别 → 保存反馈；同页保留改密、当前退出及当前密码/二次确认的永久注销。自己改密撤销其他会话、管理员重置撤销全部会话；所有新增个人数据在注销范围内。
6. **成长与奖励**：有效生成自动签到 → 成功复习按稳定原词去重掌握 → 成就/等级达成 → 在账号成长手动领取（不可用卡阻止整档，积分/经验随领取）→ 兑换中心花积分 → 道具卡启用 → 按来源叠加和到期。补签、最高等级、降级资格、模型下架与退换按当前能力独立处理。
7. **预设试用**：管理员填写一个不分界面语言的标题及完整配置（无预设说明字段）→ 不限次独立计量预览 → 有效预览后手动发布 → Header 独立试用目录 → 我也试试 → 独立工作台锁定全部预设配置 → 用户显式开始 → 扣访客/本人次数 → 原生成和认证收录流程。草稿不影响线上，参数变更需重新成功预览；仅改标题可沿用有效预览但仍须发布。收录后的私人批次沿用词条默认标题并可由本人修改，与公开预设分别管理；失效不静默代换。
8. **后台管理**：概览/数据分析同指标 → 模型密钥和完整增改启停移除 → 四个基础计划完整权益/优先级 → 用户搜索、基础计划调整/额度重置、密码重置、只读学习库/等级积分 → 成长动态多档/道具运营 → 独立消息编辑显示/提醒 → 预设发布。每类变更有失败/成功反馈与明确生效范围。

## 数据与范围约束

保留现有账号、批次、词表及原统计；二期成长从启用后累计，不回填一期签到、掌握、经验、积分或收录成就。旧批次二期首次全对仍可增加新掌握；未来词库扩充不改变同词身份，但雅思/托福/托业词库、导入和分类管理不在本期。

本期做签到与成就，不建设每日/每周/指定任务平台；学习计划留第三期。不新增商业支付、公开分享、个人私信、已读未读、称号佩戴、自助找回密码、任意 Prompt、管理员代学、原生成续传或模型调优平台。

[USER-COMPAT-001](../../M001/reviews/first-release-compatibility-policy.md) 与 [USER-CLAIM-DELETE-001](../../M001/reviews/claimed-batch-delete-retention-exception.md) 保持有效：不自动批准旧版兼容；主动删除批次时同事务清除对应已消费承接记录，原凭证不可重建，其他已消费记录保持原 24 小时规则。产品语义替代不授权技术直接清库。

本次五项需求已有用户明确来源，无新增待选业务方案。下一责任环节限定接收 CR025，按当前完整基线制作可验收设计；消息比例、具体主题、控件视觉和首页文案由设计定稿。设计定义准确双语 UI 文案、布局、交互与无障碍；批次和预设标题按 D2-81/82 显示单一原文值，技术定义结构/API/事务/性能与验证策略，但不能删减当前规则。静态文档检查不能替代产品批准、独立交接接续或应用验收。
