# 配置导入导出交互

## I501 · 宿主页入口

侧栏的模型、计划和成长入口始终生成 /formal/ 绝对路径，保留当前语言；浏览器前进、后退和刷新仍回到同一正式宿主。两个次级按钮插入原 page-head 操作组的最前面，原“添加服务商”“优先级”等按钮顺序和行为不变。成长运营在每次打开导入或导出时读取当前选中 tab：道具 tab 对应 items；签到、等级和成就三 tab 均对应完整 growth，原 tabs 仍切换原页面内容。导出完整类别，不受当前 tab、筛选或分页影响。

## I502 · 导出

打开后焦点进入关闭按钮。模型普通导出明确“不含 Key”。勾选“包含 API 密钥（加密）”后才显示两次文件口令；不一致时原地报错并保留输入。准备动作在设计稿中只显示本地成功说明，不触发下载或加密。

## I503 · 文件与解密

“选择演示文件”模拟文件选择。模型文件进入解密态，输入非空后才能“解密并校验”；其他类别直接进入预览。reading 状态阻止关闭并声明未写配置。错误按类别、配置项和字段定位，绝不展示 Key 或口令。

## I504 · 逐项预览

预览按新增、更新、移出顺序显示计数和可折叠项目。每项给出显示名、安全 identity、业务字段变化；省略字段有确定应用结果时另列说明。跨类别引用和道具历史使用 blocked 状态，不提供提交动作。

## I505 · 完整确认

确认页顺序改为移出、新增、更新；移出组默认展开。管理员勾选“已核对移出项与影响”后，“替换此类别全部配置”才可用。取消关闭 modal、恢复入口焦点且不改变宿主页。

## I506 · 提交与结果

submitting 禁止关闭与重复提交。success 只声明所选类别已替换。unknown 只提供“查询本次结果”和“读取当前配置”；二者在原型中进入确定性成功态，实际实现必须查询服务端结果。

## I507 · 原有交互隔离

新入口使用 data-cr313-action，原模块继续使用 data-action。CR-313 使用独立 #cr313-dialog；模型 #admin-model/#model-discard 和 M002 公共 #dialog 保持原事件与焦点规则。计划 #priority-editor 保留旧字段、文案与 data-action，只由 formal adapter 在每次重绘后从页面内 `<dialog open>` 提升为 `showModal()`。MutationObserver 补回入口并执行这项有限提升，不修改原 panel、表格或表单。

## I508 · 键盘与焦点

打开保存 opener，关闭后恢复。Tab 在 CR-313 modal 内循环，Escape 在 file、preview、confirm、result 可关闭，在 reading、submitting 无效。原模型与道具编辑 modal 的键盘行为由继承模块继续负责；R3 为档位优先级补齐同样的 top-layer 边界、Tab 循环、Escape 关闭和入口焦点恢复。确认与危险动作使用完整可读名称。

## I509 · Motion

modal 只使用原设计的短淡入；spinner 在 reduced motion 下停止旋转并保留 pending 文案。任何 motion 都不承担状态含义。

## I510 · 档位优先级 modal

点击原“档位优先级”入口后，编辑器居中进入 top layer 并显示继承遮罩；背景链接和控件不可操作。初始焦点进入第一个档位输入。点击“保存修改”触发原预览重绘，adapter 在重绘前记录四个输入值、重绘后恢复输入并重新调用 `showModal()`，焦点进入影响说明；“确认”执行原保存动作。取消、右上角关闭和 Escape 明确结束本轮编辑并回到“档位优先级”入口。遮罩点击不关闭，以免无确认提示时意外丢弃输入。
