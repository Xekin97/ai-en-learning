# 生成流协议、取消通道与 M001 运行拓扑

## 决策问题

CAP-008/009 必须区分“用户主动取消”和“浏览器刷新、关闭、网络断开”：主动取消计数且不退款，被动断流退款。仅依赖 HTTP 连接关闭无法区分两者，因此需要确定浏览器与 Go 后端之间的流协议、显式取消通道，以及 M001 是否为多实例协调引入额外机制。

## 已确认约束

- OpenRouter 的流式响应使用 SSE；开始输出前的错误是普通 HTTP JSON，开始输出后的错误只能作为流内事件返回。官方说明中断上游连接可以请求取消，但并非所有提供方都会立即停止处理或计费。[OpenRouter Streaming](https://openrouter.ai/docs/api_reference/streaming)
- Go `net/http` 的 `ResponseController.Flush` / `Flusher` 可逐块刷新响应，但代理可能缓冲，因此部署还必须禁用流式路由缓冲并允许长连接。[Go net/http](https://pkg.go.dev/net/http)
- 产品不支持生成跨刷新恢复、不承诺响应时间 SLA，也不需要离线、消息队列或多区域运行。
- DBA 要求模型调用位于数据库事务之外；生成开始、取消、失败和完成使用幂等状态转换；同一主体最多一个活跃生成。
- 用户主动取消必须先形成 `user_cancelled` 终态，再中止 OpenRouter；仅发生连接关闭则形成 `stream_failed` 并退款。二者竞争时只能有一个数据库终态成功。

## 可选方向

### 方向 A：单次 POST 返回 SSE + 独立取消接口 + 单应用实例

- 浏览器 `POST /api/v1/generations/stream` 提交完整白名单配置；预检失败时在发送流头之前返回普通 Problem JSON。
- 预检通过后返回 `text/event-stream`。首个事件给出本次 `run_id` 和仅用于当前交互的能力令牌；后续发送短文增量、心跳、完成或流内失败事件。
- 用户点击取消时，浏览器先调用 `POST /api/v1/generations/{run_id}/cancel`；后端以数据库 CAS 写入 `user_cancelled`，再取消当前 Go `context` 并关闭上游 OpenRouter 流。取消接口返回后浏览器终止读取。
- 页面刷新、关闭或网络断开不会调用取消接口；生成处理器从 `request.Context().Done()` 得知连接消失，以 CAS 写入 `stream_failed` 并退款。
- M001 部署一个应用进程/副本，进程内仅保存不可恢复的活动取消函数；全部正式状态仍在 PostgreSQL。进程启动时把上次异常退出遗留的 `active` 运行结算为 `server_failed`。
- 收益：最贴合“不恢复”的产品语义；请求、流和被动断开天然同生命周期；无需 WebSocket、Redis、消息队列或 PostgreSQL 通知协调。
- 代价：M001 只能运行一个应用副本，滚动发布需要先排空或把活动生成结算为失败退款。
- 风险：OpenRouter 明确指出部分提供方不支持通过断开立即停止处理，因此产品额度可按本地规则结算，但外部成本可能已经发生；必须作为运维指标记录。
- 适用条件：首版没有并发/可用性 SLA，优先保证语义正确和实现可验收。

### 方向 B：两步创建 + GET SSE + PostgreSQL 通知协调多实例

- 第一步 POST 创建运行并返回 `run_id`，第二步 GET 建立 SSE；取消接口通过 PostgreSQL `LISTEN/NOTIFY` 通知持有该运行的实例。
- 每个运行需要实例租约或心跳来判断所有者崩溃，仍禁止事件重放和断线恢复。
- 收益：可同时运行多个应用副本，取消请求不依赖命中原实例；部署可用性更高。
- 代价：需要额外租约、通知监听、失联检测和两步竞态处理；使用 PostgreSQL 承担临时协调职责。
- 风险：显著扩大数据库与后端方案；当前无规模或可用性目标证明有必要，且可能需要返回 DBA 补充字段/不变量。
- 适用条件：M001 上线即要求多副本或无中断滚动发布。

### 方向 C：WebSocket 双向生成通道

- 在同一 WebSocket 上提交生成、接收增量并发送取消指令；HTTP REST 仍处理其他业务。
- 收益：取消和流式数据天然双向，连接身份明确。
- 代价：增加独立协议、心跳、消息关联、代理配置、测试替身和前端状态机；认证、CSRF/Origin 与断连终态仍需单独设计。
- 风险：多副本下仍需要粘性路由或跨实例协调，WebSocket 本身并未解决核心一致性问题。
- 适用条件：未来需要同一连接承载多种实时双向能力，而不只是一次生成。

## 角色建议

`PROPOSED`：选择方向 A。

M001 没有多副本或可用性 SLA，且明确禁止刷新恢复。单 POST SSE 把“这次浏览器交互”与流生命周期保持一致；独立取消接口提供主动取消的可验证证据；PostgreSQL CAS 决定唯一计量终态。单实例是明确约束而非隐藏假设，未来出现多副本需求时再以压测和部署目标触发方向 B。

## 用户决定

`CONFIRMED`：用户选择方向 A，并确认：

1. 生成由 `POST /api/v1/generations/stream` 在一次请求中建立 SSE 流；发送流响应头前的预检失败使用普通 Problem JSON。
2. 用户主动取消必须调用独立取消接口；后端先用数据库 CAS 形成 `user_cancelled` 终态，再取消进程内 Go `context` 与 OpenRouter 上游流。
3. 浏览器刷新、关闭、离开或网络中断不调用取消接口；生成请求上下文结束后以 `stream_failed` 结算并退款。
4. M001 只运行一个应用进程/副本；活动取消函数只存在于该进程内，正式状态和唯一终态保存在 PostgreSQL。
5. 进程异常退出或重新启动遗留的活跃运行结算为服务端失败并退款；优雅发布先停止接收新生成，再等待或失败结算活动生成。
6. OpenRouter 提供方可能在连接取消后继续处理或计费；平台仍按已确认的本地额度规则结算，并把这种外部成本差异纳入运维指标。

## 影响范围

- 确认后固定生成 API、取消幂等规则、事件帧、关闭检测、部署副本数、优雅停机和测试矩阵。
- 不改变产品“不恢复”、额度退款、单活跃请求或数据库 T2/T3 状态语义。
