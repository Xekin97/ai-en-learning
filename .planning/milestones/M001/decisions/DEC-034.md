# 独立 Docker 构建文件与根级 Compose 编排

## 决策问题

[`DEC-033`](./DEC-033.md) 已确认单仓库内 `backend/`、`frontend/`、`nginx/` 分离并各自独立部署，但用户原始结构中的根级 `dockerfile` 尚未明确是一个全仓库 Dockerfile、一个 Docker 配置目录，还是统一编排入口。需要固定构建上下文，避免实现阶段再次把前后端耦合进同一镜像。

## 已确认约束

- 后端、前端是独立进程和独立发布单元。
- Nginx 是 M001 外部同源入口；未来可由 Kubernetes Ingress 替换。
- 根级部署入口只负责组合，不得成为前后端共享运行时。
- 每个应用必须能独立构建、测试、探活、启动与回滚。

## 可选方向

### 方向 A：每个组件独立 Dockerfile，根级 Compose（推荐）

- 结构：`backend/Dockerfile`、`frontend/Dockerfile`、`nginx/Dockerfile`、根级 `compose.yaml`。
- 收益：构建上下文最小、镜像职责清楚、CI 可按目录执行，未来可直接映射为三个独立镜像与 Deployment/Service。
- 代价：存在三个 Dockerfile，需要分别维护基础镜像与安全基线。
- 风险：若根级编排没有合同测试，服务名、端口或健康检查可能漂移。
- 适用条件：当前单仓库、独立应用部署与未来 Ingress 演进目标。

### 方向 B：根级多 target Dockerfile

- 结构：一个根级 Dockerfile，分别以 target 构建 backend、frontend、nginx 镜像。
- 收益：Docker 语法和部分构建配置集中。
- 代价：每次构建都以整个仓库为 context；缓存、忽略规则、权限和 CI path filter 更难隔离。
- 风险：target 间容易出现跨目录 `COPY`，形成隐式前后端构建耦合。
- 适用条件：组件需要共享大量构建阶段；当前项目没有该证据。

### 方向 C：一个前后端合一镜像

- 收益：表面上只有一个容器。
- 代价：无法独立发布或扩缩 Nuxt 与 Go，停机、探活、日志和回滚边界混合。
- 风险：直接违反 DEC-033，不可选。
- 适用条件：无。

## 角色建议

`PROPOSED`：选择方向 A。根目录不保留全栈 `Dockerfile`；用户原始结构中的 `dockerfile` 由三个组件内的 `Dockerfile` 和根级 `compose.yaml` 共同落地。根级 Compose 只用于本地/单机组合与端到端验证，不作为生产运行时耦合边界。

## 用户决定

`CONFIRMED`（2026-09-01）：选择方向 A。采用 `backend/Dockerfile`、`frontend/Dockerfile`、`nginx/Dockerfile` 与根级 `compose.yaml`；根目录不保留全栈 Dockerfile，三个组件继续保持独立构建、发布与回滚边界。

## 影响范围

- [`technical/deployment.md`](../technical/deployment.md)、[`technical/backend.md`](../technical/backend.md)、前端技术设计、根级 README、Compose、CI 与实现迁移计划。
- 若批准方向 A，后端实现阶段移动现有根级 Dockerfile 到 `backend/Dockerfile` 并重写 build context；前端与 Nginx 分别补充自己的 Dockerfile。
