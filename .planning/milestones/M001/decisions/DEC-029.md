# 供应商无关生成契约、M001 AI 适配策略与失败重试

## 决策问题

CAP-008/009 既要求用户逐步看到英文短文，又要求流结束后得到短文标签、逐词条释义、提示短语和可验证挖空位置组成的唯一完整批次。M001 只交付 OpenRouter，但未来可能接入 OpenAI API 或其他中转站，因此需要区分不随供应商变化的内部生成契约与 M001 的具体适配策略，并确定模型启用门槛、重试、成本和退款路径。

## 已确认约束

- 用户每次显式选择一个管理员分配的模型，服务端不能在用户不知情时改用另一模型；组别差异只体现在允许模型、长度、词数和额度。
- 整个生成批次原子成功或失败；流中片段不能保存，结构、词数、目标覆盖、语言、标签或挖空定位任一失败都退款。
- `CONFIRMED`：未来允许扩展 OpenRouter 之外的模型源，但这不是 M001 交付范围。浏览器生成 API、领域校验与学习数据不能依赖某一家供应商的字段或事件名；新模型源通过后端适配器接入。
- OpenRouter 对兼容端点支持带 `strict: true` 的 JSON Schema 结构化输出，也支持在 `stream: true` 时流式返回部分 JSON；但支持是端点级而非只看模型 ID，且不同提供方的严格程度可能不同。[OpenRouter Structured Outputs](https://openrouter.ai/docs/guides/features/structured-outputs)
- OpenAI 官方 Responses API 当前也同时提供 SSE 流式事件与 `json_schema` 结构化文本格式，因此可由独立适配器映射到同一个内部契约，而不要求浏览器理解 OpenAI 事件。[OpenAI Responses API](https://developers.openai.com/api/reference/cli/resources/responses/methods/create)
- OpenRouter Models API 暴露模型的 `supported_parameters`，其中 `structured_outputs` 表示 JSON Schema 支持；运行请求可以用 `provider.require_parameters: true` 排除不支持所需参数的提供方端点。[OpenRouter Models](https://openrouter.ai/docs/guides/overview/models)
- OpenRouter 默认可在同一个模型的多个提供方之间故障转移；`provider.allow_fallbacks` 控制提供方 fallback。跨模型 fallback 是另一机制，会改变用户实际选择的模型。[OpenRouter Provider Routing](https://openrouter.ai/docs/guides/routing/provider-selection)
- DBA 已固定流式分块不写库；完整响应只能在应用内缓冲、校验后一次写入 `generation_drafts`，模型调用期间不得持有数据库事务。

## 可选方向

### 方向 A：供应商无关内部契约 + M001 原生结构化流适配器

- 领域层只认识 `GenerationSpec`、`PassageDelta`、`GenerationCandidate`、`ProviderUsage` 和统一失败类别；供应商事件、密钥、模型原始 ID、路由参数和 JSON 分块都停留在 `AIProviderAdapter` 内。
- M001 的 `OpenRouterAdapter` 对 `/api/v1/chat/completions` 发起一次请求，固定用户选择的唯一 `model`，设置 `stream: true`、`response_format.type=json_schema`、`strict: true`、`provider.require_parameters=true` 和同模型提供方 fallback；不提交跨模型 fallback 列表。
- 输出 schema 只允许根层 `passage`、`tags`、`targets`。`targets` 顺序与输入一致，每项只含原始词条、情境释义、提示短语、提示表面形式和短文表面形式；所有对象使用 `additionalProperties:false`。
- schema 与系统指令把 `passage` 放在首位。后端用有界状态的增量 JSON 字符串解码器只把已经完整解码的 `passage` 字符发送为客户端 `passage.delta`；模型原始 JSON、其余未校验字段和内部提示不透传给浏览器。
- 模型不负责给出字符偏移。流完成后，服务端按英文词/短语边界查找模型声明表面形式的全部精确匹配，重复出现全部记为 occurrence，再转换为数据库约定的 Unicode code point、0-based、half-open 区间；找不到、同一表面形式被两个目标争用、边界冲突或目标缺失均判完整性失败。
- 管理员可以保存未启用的 OpenRouter 模型配置；启用前必须由服务端 Models API 确认 `structured_outputs` 支持，并通过固定最小参考样本。运行时仍设置 `require_parameters=true`，因为端点能力可能变化。这个门槛只约束 M001 的 OpenRouter 原生适配策略，不是所有未来模型平台的永久产品门槛。
- 未来适配器必须声明能力与执行策略：原生结构化流可直接映射；只有普通文本流的平台可新增受控分隔解析；需要二次整理的平台可新增两步策略。后两者会改变成本与失败状态，实施前必须形成新的技术决策，但不改变浏览器 SSE 或领域候选结构。
- OpenRouter 可以在同一所选模型的兼容提供方间自动 fallback；应用自身不发起第二次模型调用。流开始前、流中或完整校验后的任何失败均按既有供应商/流/校验失败结算和退款，由用户决定是否重试。
- 收益：一次调用即可得到原子结构和可感知进度；不会偷偷换模型；成本和计量边界清楚；JSON Schema 显著减少自定义文本协议失败。
- 代价：需要实现并充分模糊测试增量 JSON 字符串解码器；M001 可启用的 OpenRouter 模型必须支持结构化输出；新增供应商仍需编写和验收适配器。
- 风险：OpenRouter 明确指出各提供方严格保证程度不同，因此服务端最终校验仍不可省略；`passage` 虽要求首字段，但提供方若延迟该字段，用户看到首段的时间仍可能变长。
- 适用条件：结构可靠性高于“任何文本模型都能配置”，且首版坚持一次调用。

### 方向 B：单次自由文本分隔协议

- 提示模型先在自定义边界之间输出短文，再输出标签和逐词条 JSON；后端按边界实时转发短文，并在末尾解析元数据。
- 收益：兼容更多不支持结构化输出的文本模型；短文开始位置更容易提前约定。
- 代价：分隔符、尾部 JSON、转义和字段完整性只能靠提示遵循；需要维护更复杂的容错解析器。
- 风险：模型可能漏掉、重复或在正文自然生成边界，导致本可用内容整批失败；自由文本协议无法获得端点级 schema 约束。
- 适用条件：允许配置旧模型或低能力模型比结构成功率更重要。

### 方向 C：两次模型调用

- 第一次只流式生成短文；成功后第二次把短文提交给同一模型，生成标签、释义、提示和表面形式结构；两次均属于用户的一次产品生成。
- 收益：第一次流是纯文本，客户端流式呈现最简单；第二次可以非流式使用结构化输出或修复插件。
- 代价：每次产品生成需要两次付费调用，等待更长；第二次必须重复提交完整短文，特长内容成本更明显。
- 风险：第一步已经产生成本后第二步仍可能失败，整个批次却必须退款；用户取消与断流时还要区分两个阶段，扩大状态机和外部成本差异。
- 适用条件：可以接受双倍调用链路以换取纯文本流，并有明确成本预算。

## 角色建议

`PROPOSED`：选择方向 A。

方向 A 把“浏览器持续看到短文 + 领域最终得到严格候选”定义为 WordWeave 自己的契约，而不是 OpenRouter 协议。M001 用 OpenRouter 原生流式结构化输出实现该契约，并把不支持该能力的 OpenRouter 模型挡在启用阶段；应用不自动二次调用。未来 OpenAI 或其他中转站可以用各自适配器实现同一契约，缺少原生能力时再明确选择兼容策略。最终服务端始终独立验证业务约束和表面形式位置，不能把任何供应商的 `strict` 当作业务校验替代品。

## 用户决定

`CONFIRMED`：用户接受修订后的方向 A，并明确：

1. 流式体验与最终学习资源结构是 WordWeave 的供应商无关内部契约，不要求所有未来模型平台原生实现与 OpenRouter 相同的流式结构协议。
2. M001 只实现 OpenRouter 原生结构化流适配器，因此 M001 启用的 OpenRouter 模型端点必须通过该能力门槛和参考样本。
3. 未来 OpenAI API 或其他中转站通过独立适配器接入；原生能力不足时允许增加自由文本兼容或两步策略，但必须先重新确认成本、失败与重试语义。
4. 浏览器 API、领域校验、额度状态机和学习批次结构不暴露或依赖供应商协议。

## 影响范围

- 确认后固定内部 `AIProviderAdapter` 边界、M001 OpenRouter 请求体、AI 输出 schema、浏览器 SSE 事件、模型启用校验、提供方 fallback、应用重试和位置推导算法。
- M001 现有数据库表无需变化；`ai_models.enabled=true` 代表已满足 M001 OpenRouter 适配策略的兼容门槛，端点能力变化造成的运行失败仍按既有退款规则处理。
- 未来增加模型源需要对凭据与模型配置做向后兼容的增量迁移，因为当前 DATA-007/008 明确属于 OpenRouter；这不改变生成运行、学习批次、复习数据或浏览器 API。
- 后端验证必须覆盖 JSON 任意分块、转义字符、代理对、属性延迟、未知字段、目标顺序、重复表面形式、歧义定位、端点不支持和中途失败。
