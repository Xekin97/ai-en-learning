# Plans保存不可生成配置后缺少批准的警告

## 发现的问题

管理员将Guest的全部模型和全部篇幅取消，额度设为0或5后可以正常保存，但刷新后也没有“当前方案已暂停生成”的后果提示。实际页面直接从方案tabs进入模型选项，而原型在两者之间有notice-warning。

保存不可生成配置是允许行为，缺失的是已批准的状态反馈；不应改成禁止保存或暗中填入默认选项。严重度MEDIUM，管理员可能让整组无法生成却看不到明确提醒。

## 证据与来源

- 上游：[PAGE-102需求](../product/pages/index.md)、[PAGE-102交互](../design/interactions.md)、[原型renderAdminGroups](../design/prototype/app.js)、[API-102](../technical/api/index.md)。
- 追踪：PAGE-102；CAP-103、CAP-021；DATA-006、DATA-008、DATA-018；API-102（关联，不改合同）。
- 当前独立候选：frontend 22ae24c0、backend e8c4ee91；[076报告](../verification/cr030-cr035-076-report.md)。
- [额度0结果](../verification/evidence/cr030-cr035-076/plans-warning-results.json)、[额度0观察](../verification/evidence/cr030-cr035-076/plans-warning-observations.json)；[额度5结果](../verification/evidence/cr030-cr035-076/plans-warning-finite-results.json)、[额度5观察](../verification/evidence/cr030-cr035-076/plans-warning-finite-observations.json)。
- [英文390实际](../verification/evidence/cr030-cr035-076/screenshots/plans-invalid-chromium-en-US-390-app.png) / [原型](../verification/evidence/cr030-cr035-076/screenshots/plans-invalid-chromium-en-US-390-design.png)；[中文额度5实际](../verification/evidence/cr030-cr035-076/screenshots/plans-invalid-finite-chromium-zh-CN-390-app.png)。

## 复现

1. 真实管理员打开/admin/plans，选择Guest。
2. 取消所有Available models和Available lengths，关闭Unlimited，额度填写0。
3. 点击Save changes；真实PUT /api/v1/admin/groups/visitor返回200，models=[]、allowed_lengths=[]、rolling_24h_limit=0。
4. 刷新页面：警告数量为0。批准原型PAGE-102 / role=admin / state=invalid同态有警告。
5. 将额度改为5，保持两类选项全空，重复保存/刷新，仍缺失。

Chromium/WebKit × en-US/zh-CN × 390/1440，两额度变体各8次复现。是1个缺陷、16个矩阵失败，不是16个缺陷。本轮只确认两类选项同时为空；不虚报仅空一个或仅零额度的组合结果。

批准文案：
- en-US：Creation is paused for this plan / Choose a model and a length to resume.
- zh-CN：当前方案已暂停生成 / 选择至少一个模型和一种篇幅后即可恢复。

## 建议变更

frontend-claire按已批准配置状态补齐后果提示，让当前配置、编辑后保存及刷新恢复时的呈现一致；保持接口→转换层→状态管理→presenter→渲染分层，不直接用原始DTO渲染。保留允许保存不可生成配置的规则、固定四组、真实额度语义、完整替换PUT和既有可访问性。

回归四组、有效/不可生成/恢复有效状态、保存/重载、双语和手机/桌面；其他既定无模型/无篇幅/零额度状态按原规范处理，不自行添加新限制或未经批准文案。保留CR035两组8px实际间距与0文字偏移，不用全局样式重置造成回退。
