# 短文填空分组表现与行内输入布局需要重新设计

## 发现的问题

PAGE-008 的短文填空尚无同词分组视觉方案；同时正文行高约为 `32.1408px`，行内输入框高度约为 `37.3125px`。输入框高于行盒，在换行或窄屏密集排列时存在相邻行重叠风险，用户已在最终 UAT 中观察到重叠。

## 证据与来源

- 最终 UAT：用户报告短文填空输入框发生重叠并要求设计确认。
- 390×844 运行样式探针：正文 `line-height: 32.1408px`，输入框高度 `37.3125px`。
- 截图：`verification/evidence/screenshots/uat-final-cloze-mobile.png`。
- 分组产品语义由 CR-015 补充；本 CR 不替产品决定答案分组规则。

## 要求变更

1. 基于 CR-015 为同组空位设计不泄漏答案的编号、形状或编号加颜色提示。
2. 不得只依赖颜色；键盘、读屏与色觉差异用户都应获得同组信息。
3. 重新定义正文行高、输入框高度/基线、换行、相邻标点及连续空位的布局规则。
4. 覆盖 320、390、720 与桌面视口，以及中英文界面文案、系统字号放大和多 occurrence 密集段落。
5. 更新浏览器原型、交互说明、响应式/无障碍合同和追踪矩阵。

## 验收条件

- 任何支持视口与字号下，行内输入框、分组标记和相邻正文均不重叠、不截断、不引起页面横向滚动。
- 同组关系可由视觉和辅助技术一致识别，但不显示单词拼写、长度或答案。
- 答错、跳过、推进、恢复时分组标记位置和含义稳定。
- 实现前已有可运行原型状态与明确尺寸/换行合同可供逐像验收。

## 不变更的影响

核心复习阶段存在可读性与作答歧义，窄屏场景不可稳定使用。

## 上游产品决定

- 2026-09-02，`DEC-035` 已确认按正文首次出现顺序建立内部匿名同词组，但不在正常视觉界面显示数字组号。
- 用户希望体验上优先为各组随机配色：同组同色，颜色在一次阶段二内不随作答、错误、语言切换或重渲染跳变；重新开始阶段时可重新配色。
- UI/UX 仍需解决无限组选色、色觉差异、辅助技术与窄屏重叠。补偿方式不得显示拼写或正常可见数字组号，可评估纹理、边框、聚焦同组联动及仅辅助技术可读的匿名组名。
- 产品修订交接时本 CR 保持 `open`，由 `designer-tony` 依据 `DEC-035` 更新原型与响应式/无障碍合同。

## 处理结果

- 2026-09-02，`designer-tony` 已依据 `DEC-035` 更新 PAGE-008 阶段二可运行原型：5 个 occurrence 演示 3 个匿名同词组，其中 `create/created`、`weave/wove` 分别共享组关系。
- 正常视觉界面不显示编号或拼写；每组随机分配颜色并叠加实线、虚线、点线或双线纹理。颜色映射保存在当前阶段视图状态，输入、判错、语言切换和重渲染不会跳变。
- 聚焦任一输入会同步强化同组空；每个空具有仅辅助技术可读的匿名字母组名。输入保持统一宽度，不按答案长度变化，DOM 的输入值、标签和提示不包含答案。
- 阶段二正文使用 `inline-flex` 空位容器、`2.25em` 输入高、`2.5em` 容器最小高和至少 `3.1` 行高；320/390/720/1280px Chromium 实测无空位相交或页面级横向溢出。
- 已同步 [`interactions.md`](../design/interactions.md)、[`responsive-accessibility.md`](../design/responsive-accessibility.md) 与 [`traceability.md`](../design/traceability.md)。

结论：设计责任已完成，状态改为 `resolved`；真实前端实现差异继续由 `CR-017` 承接。
