# 分页成功响应遗漏显式空游标并阻断前后端集成

## 发现的问题

API v1.2 要求所有 keyset 列表在末页显式返回 `next_cursor: null, has_more: false`。实际组合环境中的末页响应省略了 `next_cursor`，而 Nuxt 前端按批准方案使用严格 Zod schema，因此学习记录和管理员用户学习库把成功响应判为契约漂移并显示错误/空状态。

## 证据与来源

- 上游产物：[`technical/api/index.md`](../technical/api/index.md) 1.3、API-007、API-103；[`technical/frontend.md`](../technical/frontend.md) 的 strict DTO 边界。
- 相关编号：CAP-012–CAP-015、CAP-022、CAP-104、CAP-107、PAGE-005、PAGE-006、PAGE-103、API-007、API-103。
- 组合环境复现：登录学习者调用 `GET /api/v1/me/batches`，末页 `meta` 只有 `request_id` 与 `has_more:false`；管理员调用 `GET /api/v1/admin/users/{user_id}/batches` 得到同样结果。
- UI 结果：[`library-diagnostic.png`](../verification/evidence/screenshots/library-diagnostic.png) 与 [`admin-user-diagnostic.png`](../verification/evidence/screenshots/admin-user-diagnostic.png) 显示“服务返回了无法识别的内容”。
- 根因证据：`backend/internal/httpapi/response.go` 的 `NextCursor` 使用 `json:"next_cursor,omitempty"`，空指针被 JSON 编码器省略。
- 隔离验证：[`ui-contract-shim.mjs`](../verification/evidence/ui-contract-shim.mjs) 只为末页补入 `next_cursor:null` 后，管理员详情可渲染；学习记录重试后也能渲染一个真实批次，证明主阻断来自此字段。

## 建议变更

1. 修改统一分页响应 DTO/编码路径，使所有 keyset 列表始终序列化 `next_cursor` 与 `has_more`；末页和空页必须显式为 `null/false`。
2. 覆盖 API-007、API-101 模型列表、API-103 用户列表与管理员批次列表等所有复用分页封装的端点，避免逐端点补丁。
3. 增加真实 JSON contract 回归，断言末页键存在而不只是 Go 值为空。
4. 通过根级 Nginx + Nuxt SSR/客户端导航复测 PAGE-005 与 PAGE-103，不以宽松前端 schema 掩盖后端漂移。

## 不变更的影响

- 学习者无法可靠查看、搜索或管理已有学习记录，也无法从列表发起单批次复习。
- 管理员无法可靠打开用户学习内容，CAP-104/107 的页面链路失效。
- 任何严格消费统一分页封装的新页面都可能在末页失败。

## 路由建议

- 应返回的责任阶段：`implementation`，由后台实现角色修复统一响应封装，前端保持严格契约。
- 是否阻塞当前工作：是；阻塞 M001 组合验收。
- 需要用户决定的问题：无，已批准 API v1.2 已明确字段可空性与存在性。

## 解决记录

`RESOLVED`（2026-09-02，`backend-ethan`）：

- 将普通成功响应与分页成功响应拆为独立 meta/envelope 类型；普通响应继续只序列化 `request_id`，分页响应无条件序列化 `next_cursor` 与 `has_more`。
- 末页和空页现在输出 `next_cursor:null, has_more:false`；非末页输出非空游标与 `true`，没有放宽前端 strict schema。
- `response_test.go` 新增真实 JSON 键存在性回归，同时断言普通成功响应不会被污染分页字段。
- Go 1.26 固定镜像下格式化、全量 race 单测、`go vet`、PostgreSQL 18 集成/race 测试和独立 backend 镜像构建全部通过。
- 代码：`backend/internal/httpapi/response.go`；测试：`backend/internal/httpapi/response_test.go`；验证记录：[`backend-validation.md`](../implementation/backend-validation.md)。
- 最终 Nginx/Nuxt 组合复测仍由 verification 在 CR-009/010 完成后统一执行。
