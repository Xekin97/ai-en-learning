# PAGE-103 精确匹配置顶未进入 API 排序合同

## 发现的问题

批准的 PAGE-103 设计要求“精确匹配置顶，其余用户名忽略大小写升序”，但 API-103 仍规定并实现为全部结果按规范化用户名、ID 升序。当前端搜索一个同时存在精确账号和字典序更早的包含账号时，精确账号不会排在第一位。

## 证据与来源

- 设计真源：`design/interactions.md` PAGE-103 明确规定精确匹配置顶。
- 技术合同：`technical/api/index.md` API-103 只规定规范化用户名和 ID 升序。
- 后端实现：`backend/internal/admin/service.go` 使用 `ORDER BY lower(username), id`，cursor 也只包含 username、ID。
- 独立复现：搜索 `qeky2nak`，实际前两项为 `aqeky2nakz`、`qeky2nak`；精确匹配位于第二。
- 证据：`verification/evidence/page103-list-audit.md`。

## 建议变更

1. 在 API-103 明确精确匹配 tier、其余结果排序以及跨页 cursor 语义。
2. 建议按 `is_exact DESC, lower(username), id` 排序，并让 opaque cursor 携带排序所需的 exact tier，避免前端跨页自行重排或重复。
3. 更新后端实现、DTO/游标测试和前端合同测试；前端继续只消费已经排序的应用模型。
4. 如果要取消精确匹配置顶，必须返回 UI/UX 并由用户重新批准，不能静默以现有 API 覆盖设计。

## 不变更的影响

用户输入完整用户名时仍可能先看到相似账号，降低管理员定位准确性；数据量增加后精确账号甚至可能不在第一页。前端单独重排第一页无法正确解决游标分页。
