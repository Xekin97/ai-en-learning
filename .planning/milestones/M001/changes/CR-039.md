## 用户已批准的方向

CONFIRMED：用户依次提出“能不能让 AI 生成一份映射数据？”、“不需要强求 AI 生成的短文里的单词就一定在词库里面”，并在确认下列方案后回复“嗯，就这样改吧”。

1. 冻结词库只约束用户选择的原始目标词。正文中的其他词、目标词的合法变形/派生词不必收录其中；不修改或扩展冻结输入词库。
2. AI 在同一次造文响应中附带“原始目标词 → 实际表面形式”的候选映射；不要求先离线生成覆盖全词库的封闭白名单。
3. 模型声明不是可信结论。后端检查映射词确实存在，并独立校验词形关系；不能将“字符串存在”或模型自报 relation/confidence 当成关系成立的证明。
4. 后端从原文自行计算位置，不信任模型 offset。全部目标仍须覆盖，顺序自由；提示和正文的全部合法重复位置继续挖空，同一位置不得归属多个目标。
5. 阶段一回答原始词条，阶段二回答实际表面形式；保留词性/释义区别，不能将派生名词的释义误标为形容词释义。

聊天 JSON 仅示意，不是已经批准的最终 schema。保留 DEC-032 的全部挖空和服务器位置真源；需要替换的是技术方案中禁止模型提供候选 surface 的策略。

## 技术设计须补齐的内容

- OPEN：确定字段、关系分类，以及正文/提示如何分别表达候选映射；定义缺失、重复、无效、漏报映射的处理。不得让映射漏报导致已识别目标的重复位置在复习中泄露。
- OPEN：可验证的独立词形关系检查方法、资源来源/许可/覆盖率和歧义处理。不能以粗糙词根/相似度、任意同义词或未知关系自动放行，也不能仅因表面形式不在输入词库而拒绝。
- OPEN：prompt/schema/validator 版本、兼容性探针、旧批次/在途生成兼容、错误分类和配额行为。优先保持现有公开 API 与数据库不变，但需由技术角色评估，不能将此推断当成已确认结论。
- OPEN：若独立校验需要新增在线模型调用、外部服务或重大依赖，须说明成本、延迟、隐私与失败行为后交用户决定；当前确认不等于批准额外付费调用。

## 定向验收要求

1. 用 QA090 S2 可见正文重建明确标记为合成的完整候选，验证 `vulnerable → vulnerability`；不能声称恢复了未观测的原始 metadata。
2. 覆盖正文普通词不在输入词库、目标派生词不在输入词库，以及输入本身不在冻结词库仍被拒绝。
3. 覆盖原词/屈折/派生、大小写、重复与交错出现、词边界、Unicode 位置、提示全部挖空。
4. 拒绝捏造关系、映射不在原文、同一 span 跨目标冲突、错误结构；不降低全部目标覆盖要求。
5. 检查保存后复习的原词答案/表面形式答案和旧批次稳定性；只回归受影响 AI/保存/复习链路，不重复全站 UI/UAT。
