# PAGE-103 从用户详情返回后滚动上下文丢失

## 发现的问题

PAGE-103 已能保留查询、已加载的三页结果和原 View 操作焦点，但从较深位置进入用户详情再返回时，页面最终被 Nuxt 导航滚动行为重置到顶部。焦点仍在视口外的原用户操作上，视觉位置与键盘位置脱节。

## 证据与来源

- 批准设计：`design/interactions.md` 与 `design/responsive-accessibility.md` 要求从详情返回时保留查询、结果集合、加载位置和焦点。
- 技术合同：`technical/frontend.md` 规定详情往返保留列表、滚动位置和原行焦点。
- 独立真实链路：46 条结果分三页加载后，在 390px 视口从第 31 条进入详情；点击时 `scrollY=5405`。
- 返回后：查询仍为原值、结果仍为 46 条、原 View 链接重新获焦，但稳定 `scrollY=0`；该元素 `getBoundingClientRect().top≈5889`，文档高度约 8613px。
- 连续两次独立运行得到相同现象；证据脚本为 `verification/evidence/cr020-cr022-retest.mjs`。

## 建议变更

1. 协调 Nuxt 路由 `scrollBehavior` 与 PAGE-103 的组件恢复时序，确保框架的默认顶部滚动不会覆盖业务保存的位置。
2. 恢复顺序应在结果 DOM 就绪后应用已保存 scroll，再聚焦原 View 操作；必要时使用防滚动聚焦或在导航滚动完成后恢复。
3. 只在“详情返回列表”意图下恢复，普通新搜索、直接打开 `/admin/users` 或切换其他管理页仍采用正常滚动行为。
4. 增加真实路由往返测试：至少加载三页、选择首屏外结果，并在 390px 与桌面宽度断言查询、结果数、scrollY、焦点和可见性同时恢复。

## 不变更的影响

管理员返回长列表后会看到顶部内容，而键盘焦点位于数千像素之外；键盘/读屏用户难以理解当前位置，视觉用户也必须重新寻找刚查看的账号。
