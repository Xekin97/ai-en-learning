# 补齐前端可类型化的成功响应与安全投影契约

## 发现的问题

`technical/api/index.md` 被定义为 M001 HTTP 契约真源，但若干由页面直接消费的接口只有自然语言字段说明，没有完整成功响应、可空性、枚举或分页游标结构。前端因此无法在不自行发明字段的前提下建立严格 TypeScript DTO、运行时解析、安全 Mock 和页面状态测试。

此外，启动投影只提供可变的 `actor.plan_label`，没有稳定的公共方案代码，也没有约定该 label 是否已经按 `ui_locale` 本地化。PAGE-009 和 PAGE-103 需要在中英文界面显示方案名称，直接按英文显示值猜测组别会形成脆弱契约。

## 证据与来源

- 上游产物：[`technical/api/index.md`](../technical/api/index.md)、[`product/pages/index.md`](../product/pages/index.md)、[`design/traceability.md`](../design/traceability.md)。
- 相关编号：API-001、API-003、API-007、API-008、API-101、API-102、API-103；PAGE-005 至 PAGE-009、PAGE-101 至 PAGE-103；CAP-012 至 CAP-022、CAP-101 至 CAP-107。
- 缺少精确成功 DTO 的位置：
  - `GET /api/v1/generation-options` 在无限额度、零额度和无下一恢复时间时的 `quota` 可空/互斥结构；
  - `GET /api/v1/me/account`；
  - `GET /api/v1/me/batches` 的顶层封装与 keyset 分页，`GET /api/v1/me/batches/{batch_id}` 的完整详情及 Unicode code point occurrence 结构，`PATCH` 后响应；
  - `GET /api/v1/me/review-sessions/{session_id}`，复习 action 的 spelling / passage_cloze item 联合、批次/会话完成 summary 与可空字段；
  - 管理员模型列表/创建/编辑/启停、固定组列表/更新、用户列表/详情/换组及管理员只读批次列表/详情；
  - 所有 keyset 列表的 `next_cursor`、`has_more` 或等价唯一约定。
- API-008 还缺少 PAGE-007 在刷新或直接访问后发现“当前未完成日期范围会话”的读取入口或等价投影；现有创建接口能复用会话，但页面在提交新日期前拿不到旧 `session_id` 和进度，无法实现已批准的独立恢复卡。
- `PUT /me/ui-locale`、生成取消、管理员凭证等段落使用了未包裹的成功对象描述，而全局约定要求 `{data, meta}`；当前未说明这些是例外还是简写。
- 安全敏感示例：复习 DTO 若由前端自行推断，很容易把完整短文、目标 surface 或提示答案带入 Mock；这与 API-008 的答案永不下发约束冲突。
- DEC-031 已确认禁止原始 DTO 进入应用状态、Nuxt payload 和渲染层。上述缺口因此还会直接阻塞 transport schema、纯 mapper、SSR 安全快照与合同 fixture 的实现，不能再由页面临时兼容。

## 建议变更

1. 为上述每个成功状态补充完整 `{data, meta}` JSON 示例或等价字段表，明确字段名、类型、必填/可空、稳定枚举和 `200/201/204` 差异。
2. 固定一种 keyset 分页投影并应用于学习库、模型和用户列表；明确空页和末页的游标值。
3. 统一普通成功响应是否必须使用全局 `{data, meta}`；若确有例外，逐接口明确，避免客户端维护两套隐式规则。
4. 给学习批次详情命名一个可复用投影，使本人接口和管理员只读接口显式复用同一结构，而不是仅写“相同内容”。
5. 增加当前未完成日期范围会话的发现契约，可并入复习范围预览或提供单独只读接口；至少返回 `session_id`、模式、固定原日期范围和批次进度，且不能混入单批次会话。
6. 把复习 item 定义为以 `stage` 区分的严格联合，分别列出 hint segments、passage segments、`incorrect_blank_ids`、错误重试、跳过、批次完成和会话完成响应；继续保证任何分支都不含正确答案或可还原隐藏文本。
7. 为用户可见方案增加稳定公共代码（例如受限枚举）供前端本地化，或明确 `plan_label` 必须由 API 按已生效界面语言返回并在切换语言后同步刷新；不得要求前端按显示字符串反推组别。
8. 不新增 OpenAPI；继续以补齐后的 Markdown 为契约真源，并让后端契约测试与前端 Mock 共用这些已命名投影。
9. 每个成功投影补齐后，明确其传输层命名和敏感字段边界，使前端可以为 DTO schema 与应用模型建立一对一、可测试的 mapper；不得以“前端按页面自行取字段”作为替代方案。

## 不变更的影响

- 前端只能把关键响应保留为 `unknown` 或自行假设字段，无法完成严格 DTO、DTO 到应用模型的 mapper、SSR 安全快照和可执行 Mock，实施阶段会在联调时反复改型。
- 复习和管理员只读页面存在测试数据意外包含敏感字段、状态分支与真实 API 不一致的风险。
- 中英文方案名称可能显示错误，或把后端显示文案硬编码成业务枚举。

## 路由建议

- 应返回的责任阶段：保持 `technical-design`，由 `backend-architect/base` 补充 API 契约后返回 `frontend-architect/base` 收口。
- 是否阻塞当前工作：不阻塞路由、SSR、组件、状态机、样式、性能和部署设计；阻塞前端 DTO/Mock 的最终确认以及技术阶段提交验收。
- 需要用户决定的问题：无；这是对已批准行为的契约完整性修复，不改变产品能力或页面交互。

## 解决记录

`RESOLVED`（2026-08-31，`backend-alex`）：

- [`technical/api/index.md`](../technical/api/index.md) 已升级为 `contract_version: v1.1`，并声明除 `204`、SSE、健康检查和 metrics 外，所有普通 JSON 成功响应统一使用 `{data,meta}`。
- 所有 keyset 列表统一为 `data.items + meta.next_cursor + meta.has_more`，明确空页、末页、cursor 绑定条件与不变量。
- API-001/002/003 改用稳定 `plan_code: basic | pro | plus | null`；管理组使用 `visitor | basic | pro | plus`。API 不再返回可变 `plan_label`，方案名称由前端 presentation 本地化。
- API-004 已把额度定义为 `limited/unlimited` 严格联合，补齐 `limit=0`、无限额度、无计费事件与 `refreshes_at` 的精确空值语义，并新增稳定 availability reason。
- API-007 已补齐学习库顶层分页、`BatchSummaryDto`、可复用 `BatchDetailDto`、Unicode code point occurrence、复习汇总和 PATCH 成功 DTO；管理员只读详情复用同一投影，列表明确移除 learner action。
- API-008 新增 `GET /me/review-sessions/active-range`；补齐 `ReviewSessionDto`、spelling/passage_cloze `ReviewItemDto` 严格联合，以及 retry/advanced/batch_completed/session_completed action outcome 联合。所有分支继续禁止答案、surface、完整未挖空内容和可还原旁路字段。
- API-101/102/103 已补齐凭据、模型、固定组、用户、换组和管理员只读批次的状态码、字段、可空性、枚举与可复用成功投影。
- [`technical/backend.md`](../technical/backend.md) 已同步 Nuxt/Go 同源拓扑、独立 HTTP projection mapper、DTO/数据库边界和跨端 raw fixture 契约测试要求；[`handoffs/backend-architecture.md`](../handoffs/backend-architecture.md) 已记录本次修订。
- 本次修改只明确既有 CAP/DATA/PAGE 行为，没有新增产品能力或页面，不需要新的用户决策。下一步由 `frontend-bob` 复核 v1.1，并补全前端 schema、mapper、SSR 安全快照和最终交接。
