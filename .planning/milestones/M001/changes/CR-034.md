# Review 零命中后缺少重新选择日期的入口

## 发现的问题

PAGE-007 默认最近 7 天无可复习短文时，日期选择器被整体替换为空态。空态要求“换个日期范围”，但只有学习记录/开始学习按钮，没有编辑范围或返回日期表单的操作。

这不仅影响从未保存内容的人：学习者明明有更早的已保存批次，也无法在 Review 选择旧日期。已有命中时，把日期改到零命中范围，同样丢失日期控件且无法改回来。

批准原型 PAGE-007 empty 也如此，所以实现与原型相等不能通过功能验收。现有 CAP-017 已确认任意合法日期范围复习，不需要增加产品能力或 API。

## 证据与来源

- [独立报告](../verification/report.md)、[机器结果](../verification/evidence/cr029-cr033/browser-extra-results.json)、[复现脚本](../verification/evidence/cr029-cr033/browser-extra.mjs)。
- [旧记录场景截图](../verification/evidence/cr029-cr033/screenshots/review-old-only-en.png)。
- 追踪 PAGE-007 / CAP-017/020/021 / DATA-012/014 / API-008。
- 原型：design/prototype/app.js 的 renderReviewRange，demo=empty 分支。
- 实现：frontend/app/pages/review/index.vue，preview.empty 时隐藏 review-setup 并显示没有日期动作的 empty-state。
- 新 frontend 1c9b43c803ce… / backend e8c4ee91a7c3…，真实 PostgreSQL + API + Nuxt + Nginx；中英文均复现。旧版假数据“有最近资料”会掩盖此问题。

## 可复现步骤

1. 在全新隔离栈执行 verification/evidence/cr029-cr033/setup.mjs、seed.mjs；只使用合成账号 qa065_learner。
2. 初始 seed 有两条 2026-08-10/11 保存记录；测试日期为 2026-09-05。登录并进入 /review。
3. 实际：提示没有资料并建议换范围，却找不到日期控件。预期：能直接编辑/恢复范围并选择历史资料。
4. browser-extra.mjs 第二段仅把一个合成批次改为当前日期，使最近 7 天命中。进入页面后 From/To 同为 44px。
5. 改为 2026-08-01 至 2026-08-02，等待预览。实际：两日期控件消失；仍无法重新选择。中英文相同。
6. 数据已随独立 tmpfs 清理，按脚本重建即可；不得在 6001 UAT/生产直接改保存时间。

## 建议变更

PROPOSED，由 designer-tony 确定最小方案：

- 推荐保留日期表单，在其旁/下方显示零命中反馈与已有学习入口；用户可连续调整，不中断任务。
- 或空态提供明确的“调整日期”动作，恢复已有草稿范围与焦点；需要定义空态/表单往返，交互步骤更多。

两者均不得自动创建复习、清空已填范围、改变日期边界/随机顺序/单篇复习或权限。无效日期、真正空库、历史有库但当前无命中须区分验收；不需要重做整站视觉。

## 不变更的影响

超过一周未学习的用户不能从日期复习进入旧记录。换到空范围后形成操作死路，阻塞已有首版核心能力，不能交 UAT。

## 路由建议

- 责任：先 uiux-design / designer-tony 补齐准确交互与原型，再 frontend-implementer/base 实现，最后 qa-quinn 独立复验。
- 阻塞：再次 UAT 交付；不阻塞已明确的 CR-031 中文“重试”文案修正。
- 用户决定：批准有限返回 UI/UX；具体最小方案在设计角色交付中确认。无需重开产品规划/后端/数据库方案。
- 额外基线说明：当前访客 h1 色值差异可追踪已批准 CR-010，全局弱文本不能直接回退。建议本次设计交付记录既有修订的覆盖边界；该颜色观察不作为本 CR 的功能根因。
