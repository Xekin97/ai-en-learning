# PAGE-008 未实现日期复习与本篇复习的两类总结

## 发现的问题

复习完成页只根据会话模式替换 eyebrow，仍共用同一个标题以及 Library/Review 两个通用链接。批准原型对日期范围和单批次分别设计了标题、说明、三项统计、返回操作与“再复习一轮/本篇”操作，并区分全部成功与存在跳过/待加强的状态。

## 证据与来源

- 上游产物：`design/prototype/app.js` 的 `renderReviewSummary` / `restartReview`，`design/interactions.md` 的 PAGE-008 总结规则。
- 相关编号：PAGE-008；CAP-018～020、CAP-022；DATA-014～016。
- 当前实现：`frontend/app/pages/review/[sessionId].vue` 对两种模式共用 `review.finished` 标题，按钮只是 `/library` 与 `/review` 链接，没有模式专用的重新开始动作。
- 用户 UAT 与静态复核记录：`verification/evidence/user-uat-visual-regressions-2026-09-04.md`。

## 建议变更

1. 在业务逻辑/展示转换层建立明确的 review summary view model，输入会话模式和 summary，输出原型规定的 eyebrow、标题、说明、统计标签和值、返回目标、主操作文案/行为。
2. 单批次完成后主操作新建该批次的新一轮并进入本篇复习；日期范围完成后主操作按原型开始新一轮日期复习，不得只导航到通用页面冒充动作完成。
3. 成功与存在跳过/未成功批次时使用原型对应文案，任何状态均不显示答案。
4. 增加单批次成功/待加强、日期范围成功/待加强四种总结的真实 E2E 与截图对照。

## 验收条件

- 本篇总结和日期总结的标题、说明、统计、按钮与批准原型分别一致。
- “再复习本篇”与“再复习一轮”执行真实的新会话/新轮次行为，返回路径与模式一致。
- 动态篇数来自会话 summary，不硬编码原型示例值。
- 总结不泄露任何正确答案；390/1440px 无溢出且 Axe serious/critical 为 0。

## 不变更的影响

用户无法区分完成的是单篇还是日期范围，也无法从总结页执行设计承诺的再次复习动作；CAP-020/022 的完成闭环不成立。
