# 管理后台固定文案、弹窗与间距未对齐批准设计

## 发现的问题

运行后台仍有多项可直接对照批准原型的偏差：英文页眉显示 `ADMIN` 而非 `ADMIN WORKSPACE`；Add/Edit model 弹窗缺少启用开关与提醒块；Replace key 的 New API Key 输入框使用米色而非白色背景；Plans 的 Available models 标题到选项间距为 0px 而原型为 8px；保存按钮显示 `Save` 而非 `Save changes`。

## 证据与来源

- 运行页与原型定量对照见 [最终 UAT 复现](../verification/evidence/uat-final-findings.md)。
- Add/Edit model：实际各 3 个文本输入、0 个 switch、0 个 warning；原型各 3 个文本输入、1 个 switch、1 个 warning。
- Replace key 输入背景：实际 `rgb(238, 232, 220)`；原型 `rgb(255, 255, 255)`。
- Plans 标题间距：实际 0px；原型 8px；按钮：实际 `Save`，原型 `Save changes`。
- 截图位于 `verification/evidence/screenshots/uat-final-actual-*.png` 与对应 prototype 文件。

## 要求变更

1. 所有 admin 页面英文页眉恢复为 `ADMIN WORKSPACE`；其他语言使用批准本地化文案。
2. Add/Edit model 弹窗恢复批准字段、启用开关、说明/警告层级与布局，并保持现有安全校验。
3. Replace key 输入表面颜色与批准 modal input token 一致。
4. Plans 恢复 Available models 的批准间距与 `Save changes` 文案。
5. 将这些具体状态加入实际/原型 DOM、computed style 和截图回归，不能只检查页面是否可打开。

## 验收条件

- 上述五项在中文/英文及桌面/移动端与批准原型无实质偏差。
- Add/Edit 的启用状态正确写入且取消不产生副作用。
- 键盘焦点、错误、禁用和提交中状态完整，无 serious/critical 无障碍问题。
- verification 使用同一复现脚本独立复验通过。

## 不变更的影响

管理员高频配置界面持续偏离已批准设计，模型状态也缺少预期的显式编辑入口，无法通过最终 UI UAT。
