# 关键学习页面存在严重级可访问性语义与对比度缺陷

## 发现的问题

Axe 对组合环境的关键页面扫描发现 serious 级问题：

- PAGE-004 模型说明文字对比度 3.66:1，低于普通小字号文本 4.5:1。
- PAGE-009 账号资料使用 `<dt>/<dd>`，父元素却是普通 `<div>` 而不是 `<dl>`，4 个节点失去描述列表语义。
- PAGE-009 两个资料标签对比度 4.14:1，危险区说明对比度 3.58:1。
- PAGE-008 复习进度文字对比度 4.14:1。

首页同一规则扫描没有 serious/critical 问题，但上述学习主流程页面未达到已批准可访问性验收。

## 证据与来源

- 上游产物：[`design/responsive-accessibility.md`](../design/responsive-accessibility.md) 第 3–7 节。
- 相关编号：PAGE-004、PAGE-008、PAGE-009、CAP-004、CAP-005、CAP-008、CAP-018–CAP-021。
- 可复现脚本：[`accessibility-diagnostics.mjs`](../verification/evidence/accessibility-diagnostics.mjs)。
- 具体选择器：`.choice-description`、`.progress-labels > span`、`.definition-list dt/dd`、`.card-subtitle`。

## 建议变更

1. 调整弱文本 token 或对应背景/字号，使普通文本达到 WCAG AA 4.5:1；不要只为单页面硬编码颜色。
2. 把账号资料容器改为语义正确的 `<dl>`，保持现有布局可用。
3. 对首页、登录、造文、学习记录、批次详情、复习、账号和三个管理员页面重新运行 serious/critical 扫描，并补充键盘焦点、checkbox 焦点保持和答案不泄漏人工检查。

## 不变更的影响

- 低视力用户难以读取模型说明、复习进度和危险操作说明。
- 屏幕阅读器无法把账号资料识别为描述列表。
- M001 不满足已批准的可访问性验收条件。

## 路由建议

- 应返回的责任阶段：`implementation`，由前端实现角色修复语义和设计 token 使用；若现有 token 无法满足，则在不改变视觉方向的前提下同步最小样式修订。
- 是否阻塞当前工作：是；存在 serious 级自动化发现。
- 需要用户决定的问题：无。

## 解决记录

- 2026-09-02 由 `frontend-claire` 完成修订：统一加深弱文本 token，并对危险区说明使用危险色强文本；模型说明、账号资料标签与复习进度均达到普通文本 WCAG AA 对比度要求。
- 账号资料父容器已改为语义正确的 `<dl>`；复习批次进度增加本地化可访问名称，原有键盘焦点样式同步覆盖实际 `button.choice` 控件。
- `pnpm test:e2e` 对公开、学习者、管理员共 13 个页面/状态分别在桌面与移动端执行 Axe serious/critical 扫描，12/12 浏览器用例通过；隔离组合环境另对 4 个关键真实页面扫描，20 项全栈检查全部通过。
- 结论：CR-010 所列 serious 级问题已消除并关闭；最终可访问性 UAT 仍由 verification 角色独立确认。
