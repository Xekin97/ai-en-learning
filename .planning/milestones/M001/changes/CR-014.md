# 跳转控件泄漏浏览器默认样式且未遵守设计系统语义

## 发现的问题

生产前端把批准原型中的视觉按钮改成 Nuxt 链接后，没有同步归一化链接样式。全局 `a` 规则保留默认下划线，而 `.nav-link`、`.identity-pill`、`.batch-row` 和认证辅助链接没有定义 `text-decoration:none`，造成顶部导航、身份胶囊、认证切换链接和管理员用户/学习内容整行跳转出现明显下划线。

此外，移动菜单和搜索入口分别使用原始字符 `☰`、`⌕`，没有使用批准图标系统，进一步暴露未归一化的原生表现。

## 证据与来源

- 英文双语言扫描中，PAGE-001–009 均检测到带下划线的 `.nav-link`；登录态页面同时检测到 `.identity-pill`；PAGE-103 检测到带下划线的 `.batch-row`。
- PAGE-002/003 的无 class 认证切换链接也显示下划线。
- CSS 根因：`frontend/app/assets/css/theme.css` 的全局 `a` 规则与 `.nav-link`、`.identity-pill`、`.batch-row`；`frontend/app/assets/css/application.css` 只对 `.admin-nav a` 做了归一化。
- 可复现脚本：[`ui-design-i18n-audit.mjs`](../verification/evidence/ui-design-i18n-audit.mjs)。
- 批准真源：`design/theme.css` 与 `design/prototype/app.js` 中的 button/link 语义和 SVG icon 输出。

## 要求变更

1. 建立生产链接/按钮基础归一化规则：视觉导航、胶囊、按钮和整行跳转不显示默认下划线，同时保持明确的 hover、active、focus-visible 和 aria-current 状态。
2. 不做无差别 `a { text-decoration:none }`；正文语义链接仍应保持可辨识，只有设计系统控件类清除默认装饰。
3. 为认证辅助动作使用批准的 quiet button/link 组件，不允许裸 `<a>` 直接继承浏览器表现。
4. `.nav-link`、`.identity-pill`、`.batch-row`、移动菜单和其他 NuxtLink 逐项审计；替换原始字符图标为批准 SVG 图标。
5. 增加双语言、访客/学习者/管理员、桌面/移动端的样式回归断言。

## 验收条件

- 除跳到主要内容链接和正文语义链接外，所有可见导航、身份胶囊、认证辅助动作和整行跳转控件的 `text-decoration-line` 均为 `none`。
- 控件在键盘焦点、hover、当前页和禁用状态下仍符合批准主题并可辨识。
- 页面不再出现 `☰`、`⌕` 等替代设计图标的原始字符。
- verification 对 PAGE-001–009、PAGE-101–103 的中英文实际页面重新运行控件样式扫描并通过。

## 不变更的影响

全站持续呈现明显的浏览器默认样式，破坏品牌一致性和控件层级；即使功能正确，也不能通过 UI UAT。
