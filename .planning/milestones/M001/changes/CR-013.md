# 全站页面结构、文案与视觉层级未对齐已批准原型

## 发现的问题

运行中的 Nuxt 前端只复用了部分颜色、背景和 CSS token，没有按已批准浏览器原型实现相应 DOM、信息架构、文案和组件状态。PAGE-001–009、PAGE-101–103 全部验收失败。

代表性问题包括：全站用字母 `W` 替代批准 SVG Logo；首页标题、CTA、视觉词语和流程卡错误；认证页丢失左侧叙事列；账户页把改密/注销弹窗动作常驻展开；模型管理常驻展开新增表单；方案设置把页签变成四组纵向长表单；用户管理拆成与原型不同的列表/详情结构。

## 证据与来源

- 完整逐页结论：[`verification/ui-design-audit.md`](../verification/ui-design-audit.md)。
- 对照截图：[`verification/evidence/screenshots/ui-design-retest`](../verification/evidence/screenshots/ui-design-retest/)。
- 可复现脚本：[`ui-design-retest.mjs`](../verification/evidence/ui-design-retest.mjs)、[`ui-design-i18n-audit.mjs`](../verification/evidence/ui-design-i18n-audit.mjs)。
- 批准真源：`design/prototype/*`、`design/theme.css`、`design/interactions.md`、`design/responsive-accessibility.md`、`design/traceability.md`。
- 相关编号：PAGE-001–009、PAGE-101–103、CAP-001、CAP-021 以及各页面映射能力。

## 要求变更

1. 以批准原型的页面结构和交互状态为实现合同，逐页重构实际 Nuxt 模板；动态数据通过现有转化层注入，不改变已批准结构。
2. 全站恢复批准的交织线 SVG Logo；中文仅显示“词涟”，非中文仅显示 `WordWeave`。
3. 修正首页、认证、造文、学习记录、详情、复习、账户和三个管理页的可见文案、标题标签、图标、字体层级、栅格、间距、卡片和动作位置。
4. 原型通过弹窗承载的改密、注销、密钥、模型、换组、重置密码动作不得常驻展开；方案配置必须恢复为单方案页签结构。
5. 访客头部保留三条主导航，由认证门解释受保护入口；学习者与管理员壳层按原型处理身份、退出、图标和侧栏信息。
6. 在中文/英文以及桌面/移动端完成逐页视觉回归，并提交实际与原型并排截图。

## 验收条件

- PAGE-001–009、PAGE-101–103 的默认态及本 CR 涉及的弹窗/空态/移动态与对应批准原型在信息架构、可见文案和视觉层级上无实质偏差。
- 首页主标题、CTA、Logo、访客导航、视觉词语和 `01/02/03` 流程卡与原型一致。
- PAGE-002/003 恢复两栏认证布局；PAGE-009、PAGE-101、PAGE-103 的高风险/编辑操作恢复按需弹窗；PAGE-102 恢复方案页签。
- `zh-CN` / `en-US` 均通过；允许动态业务数据不同，不允许以数据差异掩盖结构差异。
- verification 使用同一组截图脚本独立复验通过。

## 不变更的影响

产品视觉身份、首屏价值表达和主要工作流均与用户已经批准的设计不一致，无法进入最终 UAT 或里程碑完成阶段。
