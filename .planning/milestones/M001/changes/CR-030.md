# 用户管理详情与只读学习资料交互未实现批准状态

## 发现的问题

用户本轮 UAT 第 4 项中已有基线的六类问题均复现：

1. 进入详情后搜索表单消失，原型 renderAdminUsers 在 detail 状态仍渲染可用搜索。
2. 英文返回按钮为 ← Back to search results，原型为 ← Back to results。
3. 创建时间使用通用本地化格式，如 Sep 3, 2026 / 2026年9月3日；原型为 YYYY-MM-DD。
4. Library 副标题 For viewing only，原型 View only。
5. 单条资料操作为 View only，原型 View。
6. 点击资料进入 /admin/users/:userId/batches/:batchId 页面，dialog 数量为 0；原型为用户详情上打开只读弹窗。

## 证据与追踪

- [独立复现](../verification/evidence/uat-detail-regressions-2026-09-05.md)；zh/en × 390/1440 均检查。
- PAGE-103；CAP-104/107/021；API-103；DATA-003/006/012/013/018。
- 真源：design/prototype/app.js 的 renderAdminUsers、renderAdminUserDetail、showAdminBatchDialog；design/interactions.md 的只读与返回状态约束。
- 实现：frontend/app/pages/admin/users/[userId]/index.vue 与 batches/[batchId].vue。仅列表 presenter 的日期修复没有覆盖详情。

## 建议实现

- 详情保留可提交的搜索组件，不只是查询摘要；提交新查询沿现有 search controller/store 流程进入结果状态。
- 保留查询、已加载结果、位置与返回焦点；统一详情日期、角色/方案投影和文案，仍沿 DTO→mapper→应用模型→presenter 渲染。
- 资料从当前用户详情打开只读 modal，具体排版以 CR-031 新批准基线为准。关闭/ESC 后回到原资料触发按钮，详情与搜索不丢失，不引入内容写操作。
- 打开不同资料必须读取对应 userId/batchId，不能沿用原型的固定首条样本。长正文、多个词条、主题标签、加载/错误/空内容均应可验收。
- 技术路由表中的详情地址可用于状态寻址，不足以授权替换弹窗交互；新设计批准后同步最小前端路由/呈现说明，无需改变 API-103。

## 验收与路由

frontend-claire 在 CR-031 设计批准后实现。独立测试必须覆盖“搜索→详情→再搜索/返回→打开不同资料→关闭恢复”，包括浏览器返回/直接进入时的安全回退、中英文和桌面/手机；列表通过不代表详情通过。
