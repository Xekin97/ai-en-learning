# Library 六项统计与空库状态偏离批准原型

## 发现的问题

PAGE-005 的六项统计 UI 未与设计稿逐项对齐；无批次时，当前实现只替换列表区域，仍复用正常 Library 页头以及可能存在的 0 值统计、搜索工具栏和日期复习入口，而批准原型为专用空库页头与单一开始学习引导。

## 证据与来源

- 上游产物：`design/prototype/app.js` 的 `renderRecords`、`design/theme.css`、`design/interactions.md`。
- 相关编号：PAGE-005；CAP-012、CAP-013；DATA-016。
- 当前实现：`frontend/app/pages/library/index.vue` 在 summary、toolbar 之后才以 `batches.length` 选择列表/空卡，无法表达原型的页面级空状态。
- 用户 UAT 与静态复核记录：`verification/evidence/user-uat-visual-regressions-2026-09-04.md`。

## 建议变更

1. 将“首次空库”作为 PAGE-005 页面级 view state，由 presenter/store 的应用模型驱动，不在模板中零散推断。
2. 空库时按原型展示专用描述、图标、标题、说明和开始学习操作；隐藏原型中不存在的统计、搜索、批次数和日期复习入口。
3. 有数据时六项统计的顺序、卡片表面、边框、字级、间距、标签和响应式列数逐项匹配批准原型；数值继续使用真实 DATA-016。
4. 搜索无结果仍是另一个状态，保留统计和搜索，不与首次空库混淆。
5. 增加空库、正常库、搜索无结果三种状态的中英文/双视口截图基线。

## 验收条件

- 正常 Library 的六项统计与原型关键尺寸/结构一致，顺序和文案完全一致。
- 首次空库只展示批准的空库页面内容；不会显示六张 0 卡、搜索栏或不可执行的日期复习入口。
- 搜索无结果保留正常页上下文并显示原型的搜索空状态。
- 390/1440px 无溢出，Axe serious/critical 为 0。

## 不变更的影响

新用户首先看到的是一组无意义的零值和不可执行入口；已有用户的核心学习总览继续与批准设计不一致。
