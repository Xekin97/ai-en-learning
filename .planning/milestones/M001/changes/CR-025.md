# 访客受限页与登录凭据错误态偏离批准设计

## 发现的问题

访客直接进入 Review/Library 时虽然不再跳转 Login，但引导卡被生产专用 CSS 改成不同宽高和版式；登录密码错误时，通用错误组件没有使用批准原型的 notice 结构，导致消息排版错乱。

## 证据与来源

- 上游产物：`design/prototype/app.js` 的 `renderAuthGate`、`renderAuth`，以及 `design/theme.css`。
- 相关编号：PAGE-003、PAGE-005、PAGE-007；CAP-003、CAP-021。
- 当前实现：`AuthGate.vue` 附加 `.auth-gate`，`application.css` 对其设置额外 max-width/min-height；`AppError.vue` 只输出裸文本和 `<small>`，缺少原型图标与内容容器。
- 用户 UAT 与静态复核记录：`verification/evidence/user-uat-visual-regressions-2026-09-04.md`。

## 建议变更

1. Review 与 Library 的访客引导在原路由内，按原型恢复卡片宽度、间距、图标、标题、说明和两个操作。
2. 登录 invalid credentials 使用原型 notice 的图标、内容容器和间距；安全错误信息仍由稳定 failure kind 本地化，不能显示后端 detail 或泄露账号存在性。
3. request id 若保留为支持信息，必须另行排版且不能破坏 notice；原型未展示时，默认不进入主要错误文案行。
4. 增加真实错误提交和两条访客直达路径的截图/DOM 对照。

## 验收条件

- 未登录访问 `/review` 与 `/library` 均停留原路由，并与批准访客引导视觉一致。
- 错误密码显示完整、稳定、不溢出的 danger notice；中英文与 390/1440px 均通过。
- 登录失败不清空用户名、不泄露用户名是否存在，并允许立即重试。
- Axe serious/critical 为 0。

## 不变更的影响

访客的注册转化入口与品牌视觉不一致；认证失败这一高频状态继续出现明显 UI 错乱。
