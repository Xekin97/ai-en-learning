# Replace key 输入表面仍未对齐批准原型

## 发现的问题

CR-018 返工后的独立验证确认，PAGE-101 的其余修订均已落地，但 Replace key 弹窗中的 New API Key 输入框仍覆盖为暖白表面。运行实现的 computed background 为 `rgb(255, 253, 248)`（`#fffdf8`），批准原型为 `rgb(255, 255, 255)`（`#ffffff`）。

## 证据与来源

- 独立脚本：`verification/evidence/v13-final-retest.mjs`，最终稳定结果 4/5 PASS，唯一失败为该 computed-style 对照。
- 运行截图：`verification/evidence/screenshots/v13-final-retest/admin-key.png`。
- 批准原型：PAGE-101 Replace key dialog 的 `.text-input` 使用 `--color-surface-raised`。
- 运行样式：`frontend/app/assets/css/application.css` 中 `.admin-key-input` 使用 `--color-surface`，覆盖了通用白色输入表面。
- CR-018 的验收条件已明确要求 Replace key 输入表面与批准 modal input token 一致。

## 要求变更

1. 移除 `.admin-key-input` 对通用 input surface 的错误覆盖，或明确改用批准的 raised/input token。
2. 不改变输入框的密码类型、焦点轮廓、校验、禁用、提交与凭据遮罩行为。
3. 增加实际页与批准原型的 computed background 精确回归，至少覆盖中英文和桌面/移动端。

## 验收条件

- New API Key 输入框在运行页和批准原型中均计算为 `rgb(255, 255, 255)`。
- PAGE-101 的 heading、Add/Edit model 结构及 Plans 已通过项不发生回归。
- 320、390、720、1440px 无溢出；目标页无 serious/critical Axe 告警。
- verification 使用现有独立脚本复验为 5/5 PASS 后，才能再次提交用户 UAT。

## 不变更的影响

用户明确指出并批准返工的视觉偏差仍然存在，M001 无法声称最终 UAT 问题已全部修复。
