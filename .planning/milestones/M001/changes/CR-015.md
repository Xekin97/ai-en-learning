# 短文填空缺少同一目标词原型的匿名分组

## 发现的问题

短文填空会挖空全部目标词 occurrence，但各空位只携带独立 `blank_id`。当同一目标词原型在正文中出现多次或发生词形变化时，学习者无法判断哪些空属于同一答案组。

用户要求按单词归属，用编号或颜色提示同组空位，同时始终不透露单词拼写。现有 CAP-019 只约定“全部 occurrence 挖空并回答”，没有定义分组身份、展示稳定性或防答案泄漏边界，因此这是产品合同缺口，不是单纯样式问题。

## 证据与来源

- 最终 UAT：用户在 PAGE-008 短文填空阶段明确提出同词分组要求。
- 运行 API 中每个正文空位仅有 `kind`、`blank_id`；9 个空位均无 `target` 或 `group` 字段。
- 后端内部 occurrence 记录知道目标词归属，但 `backend/internal/httpapi/review_handlers.go` 的公开映射会丢弃该信息。
- 前端 review schema、转化层和视图模型同样只接收 `blankId`。
- 可复现证据：[最终 UAT 复现](../verification/evidence/uat-final-findings.md)与 `verification/evidence/uat-final-findings.mjs`。

## 要求变更

1. 为每篇短文内属于同一目标词原型的所有空位定义稳定、匿名的分组标识或序号。
2. 同一原型的词形变化仍归入同组；不同原型不得误归组。
3. 分组信息只表达“相同/不同”，不得包含原词拼写、可逆 ID、答案长度或其他答案线索。
4. 定义单词只出现一次、多次、多个原型交错、跳过与恢复会话时的分组行为。
5. 将语义补入 CAP-019、PAGE-008、DATA/API 追踪与验收条件，再交由 UI/UX 选择可访问的视觉表达。

## 验收条件

- 一篇短文内，同一目标词原型的全部空位获得相同匿名组，其他词获得不同匿名组。
- 分组顺序在一次复习项目的首次呈现、答错重试和恢复后保持稳定。
- 客户端和接口均不能从分组载荷推导目标词拼写或答案长度。
- 颜色不是唯一的信息载体；具体编号、形状或可访问名称由 UI/UX 合同定义。
- API、转化层、界面与自动化测试覆盖单次、多次及词形变化 occurrence。

## 不变更的影响

多词、多 occurrence 的短文填空缺少必要作答上下文，用户无法可靠判断答案复用关系，CAP-019 无法通过最终 UAT。

## 解决记录

- 2026-09-02，用户在 `DEC-035` 选择方向 A：内部匿名组序按目标词条在正文中的首次出现顺序确定；同一原型的所有相同/不同自然词形同组，不同原型不同组，每个空仍单独填写实际表面形式。
- 用户进一步确认正常视觉体验可以随机颜色分组，不显式显示组号。产品规定颜色映射在一次短文填空阶段内保持稳定；重新开始阶段时可重新配色，组关系不变。
- 颜色不足、色觉差异和辅助技术由 UI/UX 使用非拼写、非显式数字的补偿方式处理；不得通过可见组号、原词或可逆 ID 泄漏答案映射。
- 已同步 `overview.md`、DATA-013、CAP-019/020、PAGE-008、`ai-behavior.md` 与产品验收；匿名分组由已校验 occurrence 派生，不增加 AI 输出字段或模型调用。
- CR-015 的产品责任已完成并关闭；CR-016 继续阻塞 UI/UX 的配色、无障碍和防重叠设计，后续技术/API 与实现仍需按批准设计同步。
