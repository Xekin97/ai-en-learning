# 用户管理缺少用户搜索结果列表设计

## 发现的问题

PAGE-103 的产品合同要求“用户名搜索与结果”以及从结果打开用户详情，但批准原型只设计了默认用户详情和空态，没有给出有多个搜索结果时的用户列表、选择及分页状态。生产实现自行补出了列表，因缺少设计真源而无法判断其信息层级、操作路径和响应式行为。

## 证据与来源

- 产品真源：`product/pages/index.md` PAGE-103 和 `product/abilities.md` CAP-104 明确要求用户名搜索、结果、无结果及用户详情。
- 批准原型 PAGE-103 只登记 `default`、`empty` 两个状态；没有多结果列表状态。
- 当前 UAT 数据下运行 `/admin/users` 初始显示 17 行，属于实现自行补全的未设计状态。
- 最终 UAT：用户明确判定这是设计产出失误并要求重新设计。

## 要求变更

1. 设计用户名搜索前、加载中、多结果、单结果、无结果、错误与分页/继续加载状态。
2. 明确列表到详情、返回结果、修改组别/重置密码及只读学习库的状态保持规则。
3. 规定列表字段、排序、分页、选中态与权限边界，不展示密码或不必要的学习隐私摘要。
4. 覆盖 320、390、720 与桌面布局、长用户名、中英文和键盘/读屏操作。
5. 更新可运行原型、交互、响应式/无障碍与 PAGE–CAP 追踪。

## 验收条件

- PAGE-103 对 CAP-104 所需的完整搜索结果生命周期都有批准设计状态。
- 多结果列表可明确选择用户并进入详情，返回时保留合理的查询和位置状态。
- 空态、错误、加载与分页不是实现自行推断；移动端不横向溢出。
- 列表及详情符合管理员只读/有限管理边界，并通过键盘和读屏验收。

## 不变更的影响

用户管理核心入口没有可验收设计合同，继续直接修改实现会重复产生设计偏差。

## 处理结果

- 2026-09-02，`designer-tony` 已为 PAGE-103 增加搜索前、加载、多结果、单结果、无结果、错误、继续加载和用户详情八个稳定原型状态。
- 结果列表仅显示用户名、角色、创建日期、当前方案和账号状态；不在列表展示密码、额度明细或学习内容摘要。长用户名可换行，320/390/720/1280px 中英文实测无页面级横向溢出。
- 结果以精确匹配置顶、其余用户名忽略大小写升序；“加载更多”延续同一结果顺序。单结果不自动跳转，管理员需明确选择“查看”。
- 从详情返回会保留查询、结果状态和刚才所选行的焦点；学习库仍只读，列表没有批量修改、删除或冒充入口。
- 已同步 [`interactions.md`](../design/interactions.md)、[`responsive-accessibility.md`](../design/responsive-accessibility.md) 与 [`traceability.md`](../design/traceability.md)。

结论：缺失的用户搜索结果设计已补齐，状态改为 `resolved`；真实前端落地由 `CR-018` 承接。
