# 访客访问复习与学习记录时绕过设计中的认证引导页

## 发现的问题

访客直接访问 `/review` 或 `/library` 时，生产前端立即跳转到 `/login?redirect=...`，没有显示批准设计中的全页认证引导，也没有同时提供“登录并继续”和“创建账号”动作。

## 证据与来源

- `frontend/app/middleware/learner.ts` 对未登录访问直接执行 login redirect。
- 浏览器复现：`/review` 落在 `/login?redirect=/review`，`/library` 落在 `/login?redirect=/library`，两页均无 auth gate。
- 批准设计：`design/interactions.md` 明确 PAGE-005/PAGE-007/PAGE-009 的访客直接访问使用 full-page reason；`design/prototype/app.js` 的 `renderAuthGate()` 提供登录与注册入口。
- 机器证据：[最终 UAT 复现](../verification/evidence/uat-final-findings.md)。

## 要求变更

1. 访客访问 `/review`、`/library` 时先渲染批准的认证引导状态，不立即跳转。
2. 引导页同时提供登录继续与创建账号，并保留原目标及必要查询参数。
3. 登录或注册成功后返回原目标；主动离开或取消不形成错误历史循环。
4. 服务端权限边界保持不变，认证引导不得加载任何私有数据。
5. 增加两个入口、两种语言、桌面/移动与键盘操作回归。

## 验收条件

- 未登录打开 `/review`、`/library` 时 URL 与画面先停留在相应认证引导状态。
- 引导结构、文案、图标和动作与批准原型一致。
- 登录和注册均能按原意图返回；无开放重定向或私有数据泄漏。

## 不变更的影响

访客关键转化路径与批准设计不符，注册入口缺失，PAGE-005/PAGE-007 无法通过 UI UAT。

## 解决记录

- 2026-09-02，`frontend-claire` 已在 `/library` 与 `/review` 原路由内实现批准的全页认证引导，同时提供登录与注册动作；访问引导时不会调用学习摘要、复习批次、预览或活动会话等私有接口。
- 登录和注册使用白名单校验后的 return intent 返回原目标；外部 URL、双斜线、反斜线、编码斜线、控制字符与管理员路径均被拒绝，避免开放重定向。
- 中英文、桌面/移动端 E2E 已覆盖两个入口、URL 保持、无私有取数、双认证动作和登录返回；开发期结论 PASS，最终独立复验仍交由 verification 角色。
