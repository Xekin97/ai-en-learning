# 重做用户资料只读弹窗，并统一注销说明视觉基线

## 用户反馈与设计问题

- CONFIRMED：用户明确否决 PAGE-103 资料只读查看的现有设计，认为间距太挤，要求重新设计；不是仅让实现复制当前原型。
- 当前原型的 notice 下沿与 passage-tags 上沿完全相接，区域间距为 0px。通用 32rem dialog 内密集呈现提示、主题和正文；[截图与量化记录](../verification/evidence/uat-detail-regressions-2026-09-05.md)。
- PAGE-009 注销说明实际为红色 rgb(135,50,50)，旧原型为灰色 rgb(109,127,126)。历史 CR-010 记录旧危险区文字对比度 3.58:1，开发为满足既有可访问性验收加深为危险色，但设计稿未同步。用户本轮拒绝该视觉差异，需要设计统一，不应直接恢复低对比度样式。

## 追踪

PAGE-103/009；CAP-107/005/021；DATA-012/013/018。输入为用户本轮 UAT、design/prototype/app.js、theme.css、interactions.md、responsive-accessibility.md 与 [CR-010](./CR-010.md)。

## 建议修订边界

1. 只重开 PAGE-103 只读资料 modal 和 PAGE-009 注销区域视觉细节，不改产品能力、AI 输出、管理员权限或 API。
2. 对只读提示、主题、正文及已批准的资料内容建立清晰分区，明确桌面/手机弹窗宽度、内边距、段间距、行距、长文滚动及关闭操作，不挤压正文阅读空间。
3. 搜索与详情作为弹窗背景保留；打开/关闭不丢当前用户、查询、资料位置。只读标识持续可见，无编辑/删除/代复习动作。
4. 明确短/长/特长正文、长标签、多词条、加载/错误等状态，不能只展示一篇固定短样本。
5. 注销说明统一文案、色彩与背景；维持已批准的普通文本 AA 对比度要求，同时满足用户希望的视觉层级。具体方案由 designer-tony 提交用户审阅，质量角色不代选色值。
6. 更新可运行 HTML/CSS/JS 原型、交互与响应式说明并同步新截图，避免批准稿与实现再次成为两套基线。
