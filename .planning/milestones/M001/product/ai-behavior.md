# M001 AI 行为契约

本轮仅修订原词释义，状态为待审阅；确认来源、历史优先级与修订前快照见[当前修订入口](./overview.md#cr040-revision)。其他已批准规则不重开。

## 1. 目标与边界

AI 的任务是把一组固定词表词条编织进一篇指定场景和最低长度的英文短文，为整篇短文产生一组语义标签，并为每个词条产生可用于学习与复习的结构化资源。AI 不接受用户自由 Prompt，不替用户回答专业问题，不生成整篇翻译，也不决定账号权益、额度或保存权限。

本契约描述产品可观察行为。模型供应商、SDK、Prompt 组织、重试策略和持久化实现由后续专业角色设计，但不得改变这里的输入白名单、输出语义、流式体验、校验结果和计量规则。

## 2. 受信输入

### 2.1 用户可选择字段

| 字段 | 允许值 | 来源/权限 |
| --- | --- | --- |
| `entries` | DATA-001 中 1 至所属组最大数量的互异 DATA-002 | 用户从搜索结果精确选择 |
| `model` | 所属 DATA-006 分配且当前启用的 DATA-008 | 用户每次显式选择 |
| `meaning_language` | 中文、英文、日文 | 全局固定，用户每次显式选择；英文表示英英释义 |
| `scenario` | 讨论、故事、商务、新闻 | 全局固定，用户每次显式选择 |
| `length` | 短、中、长、特长中所属组允许的值 | 用户每次显式选择 |

用户没有其他 AI 输入字段。产品不保存或自动恢复上一次选择；未完成全部选择不能开始生成。

DATA-018 界面语言不属于 AI 输入字段。切换 `zh-CN` / `en-US` 不得自动修改 `meaning_language`，也不得翻译或重新生成已经返回的释义、短文标签或英文短文。

### 2.2 服务端预检

模型调用前必须依据服务端真实状态完成以下产品级判定：

1. 请求身份是当前 DATA-003 或 DATA-005，且没有另一活跃请求。
2. 请求字段集合与类型完全符合白名单；未知字段、自由文本、额外指令或伪造标识直接拒绝。
3. 每个词条精确存在于冻结 DATA-001，词条互异且数量不超过组上限。
4. 模型已启用且属于当前组；长度属于当前组；语言与场景属于固定枚举。
5. 当前组存在可用模型和长度，额度不为零且滚动 24 小时仍有余额。
6. DATA-007 已有效配置。

预检拒绝不得调用模型、创建可计数生成或占用额度。客户端控制只用于体验，不能替代上述服务端判定。

## 3. 输出语义

一次完整结果必须是单个结构化生成批次，包含以下内容：

### 3.1 英文短文

- 一篇连贯英文短文，不是互不相关的单句集合。
- 语气与内容符合所选场景，并保持中性、教育性、适合一般受众。
- 必须覆盖每个输入词条至少一次，允许采用语法自然的词形变化。
- 不提供整篇短文翻译。
- 长度只验证英文词数下限，不设置上限：短不少于 50 词，中不少于 100 词，长不少于 200 词，特长不少于 400 词。
- 超过所选档位下限很多仍属于长度有效；产品不会自动截断。

### 3.2 短文标签

- 一篇短文必须且只能包含一组 `tags`，数量为 1–3 个。
- 标签描述整篇短文的主题或语义，不描述单个目标词条。
- 标签使用本次选择的目标语言；选择英文时生成英文标签。
- M001 只展示标签，不支持按标签搜索、筛选或编辑。

### 3.3 每词条学习资源

每个输入词条必须且只能对应一组资源：

- `source_entry`：原始 DATA-002，必须与输入精确对应。
- 原词释义：针对输入的原始 DATA-002 本身，用所选目标语言给出简洁词义/定义；选择英文时使用英文定义。每词条仍对应一条释义内容，具体语义边界如下。
- `hint_phrase`：一个包含该词条或其自然词形变化的英文短语，不提供短语翻译；允许同一目标在短语中出现一次或多次。
- `hint_occurrences`：提示短语中属于该目标词条、需要同时挖空的全部实际表面形式和精确位置，至少一处。
- `passage_occurrences`：短文中该目标词条所有用于复习的实际表面形式和精确位置，至少一处；同一目标下的相同或不同自然词形在短文填空时属于同一匿名组。

词条资源顺序应与用户提交词条顺序一致，以便稳定呈现；复习时另按 DATA-014 固定随机顺序展示。

#### 原词释义边界（CR-040）

`CONFIRMED`：用户明确“这个释义仅仅只针对用户输入的单词，和生成的文章、派生都无关”，并要求去掉文中作用提示；来源为[CR-040 用户澄清](../verification/cr040-meaning-only-request.md)。本节是该规则的唯一产品语义定义。

- 释义对象及语义依据仅为用户输入的原始词条和所选释义语言；不根据文章、场景、短语或实际表面形式/派生映射选择、限定或改写词义。短文标签仍描述文章，不能与原词释义混淆。
- 只表达词本身的词义，不附带文中作用、剧情解释、句法分析或“在本文中……”之类提示。单纯删除这些尾句但继续按文章选义，仍不符合要求。
- 输入原词与正文派生词的释义不可互换。正文出现 `vulnerability` 时，输入 `vulnerable` 的释义仍解释原词本身；映射只服务目标覆盖、位置和复习，不回流决定释义。
- 一条释义内容可以包含简洁的近义解释，不把分号视为需要截断的作用说明；不新增固定义项数、穷尽词典义项或多次生成逐字一致的要求。多义词也不得通过文章挑选或排除义项。
- 新生成内容在造文展示、保存后查看和第一阶段复习中使用同一份原词释义；不在前端截尾掩盖原始内容，也不在复习时根据文章重新释义。本轮不批量重写已有批次。

以下为人工编写的语义示例，不是真实模型测试结果，也不锁定唯一文案：

| 输入原词 | 释义语言 | 合理示例 |
| --- | --- | --- |
| alleviate | 中文 | 缓解；减轻 |
| vulnerable | 中文 | 易受伤害的；脆弱的 |
| vulnerable | 英文 | Easily harmed or damaged. |
| vulnerable | 日文 | 傷つきやすい；弱い |

不合格示例：给 `vulnerable` 解释为“脆弱性”（解释了派生名词），或“易受伤害的；在本文中描述社区面临风险”（附加文章作用）。例句/短文可以帮助学习，但不能反过来决定上述释义。

### 3.4 产品语义结构示例

以下示例只表达字段含义，不是对具体传输格式或键名的技术锁定。`entry_meaning` 只是“原词释义”的示意名；现有 `contextual_meaning` 的实际命名、传输和存储影响须由后续技术修订明确，本产品修订不批准 API 改名或旧版兼容方案：

```json
{
  "passage": "An English passage containing every selected entry...",
  "tags": ["协作", "社区"],
  "targets": [
    {
      "source_entry": "create",
      "entry_meaning": "创造；创作",
      "hint_phrase": "creating together while creating a shared plan",
      "hint_occurrences": [
        { "surface": "creating", "location": "..." },
        { "surface": "creating", "location": "..." }
      ],
      "passage_occurrences": [
        { "surface": "created", "location": "..." }
      ]
    }
  ]
}
```

最终技术契约可以采用适合模型结构化输出的定位方式，但必须能无歧义地重建提示短语和短文的全部目标挖空，不能在复习时重新让模型猜测位置。提示短语中的多个空共同构成一道词条拼写题，学习者只提交一次原始词条答案。

### 3.5 短文填空匿名分组派生

匿名同词分组不是新增 AI 生成内容，也不要求模型输出组号或颜色。完整候选通过 occurrence 校验后，产品服务从短文开头扫描全部 `passage_occurrences`：第一次遇到某个 `source_entry` 时建立下一内部组序，该目标后续所有相同或不同自然词形复用该组；不同目标不得共享组。

学习者侧只得到表达同组关系所需的匿名投影，不得到 `source_entry`、原词拼写、可逆词条 ID 或答案长度。正常视觉体验可在每次进入短文填空阶段时为组随机配色，组序本身不显示为数字；配色在该阶段的作答、错误重试、语言切换和重渲染期间保持不变。颜色不足、色觉差异与辅助技术的补偿由 UI/UX 定义，但不得把拼写或可见数字组号重新暴露给学习者。

## 4. 完整性校验

流结束后，结果只有同时满足以下条件才成为“有效结果”：

1. 可解析为唯一完整批次，且没有缺少、重复或未知目标词条。
2. 英文短文达到所选长度下限。
3. 每个目标词条至少有一个经验证的短文表面形式；允许词形变化，但不能仅凭模型声称覆盖。
4. 每个词条恰有一条非空目标语言原词释义和一个非空英文提示短语；释义语义遵循[原词释义边界](#original-entry-meaning)。
5. 整个批次有且只有一组 1–3 个非空目标语言标签；任一词条资源均不包含独立标签。
6. 提示与短文的全部表面形式、位置均能与原文精确对应，彼此不冲突且足以挖空；提示短语中属于该目标的每个已验证位置都必须纳入，不能留下可见的同目标重复位置。
7. 每个短文 occurrence 无歧义地归属且只归属一个目标资源，使服务端可确定性派生匿名同词组；同一位置被多个目标争用时整批失败。
8. 结果不包含产品未要求的自由指令回显、密钥或内部系统内容。

任何一项失败，整个批次无效，不允许部分保存。产品显示可理解的“本次生成未通过完整性校验，请重试”，丢弃临时结果，并按系统失败退款。M001 不向用户展示原始结构解析详情或正确答案。

结构、非空、语言或词形关系校验通过，不能证明释义语义准确或独立于文章。该质量边界必须按第 9 节定向评阅；本修订不新增在线语义审核、第二次模型调用或新的自动拒绝/退款判定机制，不能将结构通过宣称为 CR-040 质量验收通过。

## 5. 流式状态机

```text
配置未完成
  └─ 完整选择并提交
       └─ 服务端预检
            ├─ 拒绝：无模型调用、无计数、可修正后重试
            └─ 通过：占用额度，建立唯一活跃请求
                 └─ 流式接收 DATA-011
                      ├─ 用户取消：停止、丢弃、计数且不退款
                      ├─ 供应商/服务端/网络中断：丢弃、退款、不计累计
                      └─ 流完成：执行完整性校验
                           ├─ 失败：丢弃、退款、不计累计
                           └─ 通过：展示完整结果
                                ├─ 登录用户保存：创建 DATA-012/013
                                ├─ 登录用户放弃：不保存，保留累计计数
                                └─ 访客保存：创建 DATA-017 后认证并一次性绑定
```

- 流式内容是等待体验，不是已保存资源；用户可以看到内容逐步出现，但保存操作只在完整校验成功后开放。
- 用户刷新、关闭、离开或网络断开视为流中断，不支持续传；结果丢弃并退款。
- 用户主动点击取消与被动中断不同：主动取消仍消耗一次额度并计入累计生成次数。
- 不设 AI 响应时间、并发吞吐或可用性 SLA；M001 只要求状态可观察且不会把失败结果保存为成功。

## 6. 额度与模型行为

- 访客、正式账号、付费 Pro、付费 Plus 均使用相同输出契约，差异只来自 DATA-006 配置的模型、长度、单次词条数与次数额度。
- 同一组可以有多个模型，用户必须在本次允许集合中自行选择一个；服务端不能接受页面之外的模型 ID。
- 学习者只看到模型名称与说明；原始 OpenRouter ID 和 DATA-007 不进入用户界面或生成内容。
- 模型、组策略在请求开始后以当时有效配置为准；后来停用模型或换组不改写保存批次。
- 访客认证承接保存沿用已经通过的访客结果，不二次调用、不二次占用、不按新账号组重跑校验；账号累计生成次数增加 1，账号滚动额度不增加事件。

## 7. 安全与内容边界

DATA-001 保留全部词条，包括已识别的暴力、性、自伤、酒精等敏感语义词条。M001 的已确认选择是：不做运行时词条过滤、AI 内容审核、第二次安全模型调用或人工审核。

风险降低措施必须包括：

- 用户只能选冻结词条与固定枚举，没有自由 Prompt、自由场景或额外指令。
- 服务端拒绝未知字段、自由文本、伪造词条/模型/枚举和越权值，拒绝发生在模型调用前。
- 系统指令要求中性、教育性、非煽动、适合一般受众的语言学习内容，不把敏感词条扩展为露骨、鼓励伤害或极端立场内容。
- 模型输出不得执行或回显词条中看似指令的文本；词条始终作为被学习的数据处理。
- 错误与日志不得暴露系统指令、OpenRouter 密钥或其他用户内容。

这些措施不能保证结果适合儿童，产品也不得作出此类宣称。若后续增加自由输入、面向特定年龄、公开分享或在新地区上线，必须重新进行产品安全和合规决策。

## 8. 可预测与概率行为

| 行为 | 必须确定 | 允许模型差异 |
| --- | --- | --- |
| 输入集合、权限、枚举、额度 | 是，由产品服务决定 | 否 |
| 输出字段、目标数量、语言、短文标签数量 | 是，校验不符即失败 | 文案可以不同 |
| 短文是否达到下限、是否覆盖每个词条 | 是 | 具体情节、措辞和词形可以不同 |
| 原词释义独立于文章与派生 | 释义对象和依赖边界必须遵循[原词释义边界](#original-entry-meaning)；结构通过不是语义证明 | 简洁措辞可不同，不要求逐字相同或穷尽所有义项 |
| 提示与挖空位置 | 全部目标位置必须可精确重建并全部遮蔽；提示仍只作答一次 | 短语内容、出现次数和表面词形可以不同 |
| 短文同词分组 | 服务端按正文首次出现顺序从已校验 occurrence 确定性派生；同一原型的全部词形同组 | 每次进入阶段二时视觉颜色可以重新随机分配 |
| 中性教育型语气 | 必须遵守 | 风格细节可以不同 |
| 流式分块数量和到达节奏 | 否 | 可以不同，但状态必须一致 |

功能验收不要求不同模型或重复调用产生相同文本；只要求每次结果符合结构和产品语义。

## 9. AI 功能验收样本

后续 AI 设计和验证至少建立以下固定参考样本；样本用于覆盖，不锁定唯一期望文案：

1. **基础单词**：1 个与 5 个普通词条，覆盖每种语言、场景和长度最低边界。
2. **词形变化**：原始词条在短文与提示中以复数、时态或派生形态出现，验证阶段一仍接受原始词条、阶段二接受实际表面形式。
3. **多词词条**：分别覆盖 `according to`、`coup d'etat`、`ought to`、`owing to` 的搜索、生成、位置保存和挖空。
4. **重复出现与同词分组**：同一目标在提示短语或短文中出现多次，包含相同表面形式和不同自然词形；提示短语全部位置同时挖空但只作答一次；短文全部位置分别正确挖空，并与其他交错目标形成按正文首次出现排序的匿名组。
5. **长度边界**：低于下限失败、等于下限通过、远高于下限仍通过。
6. **英英学习**：释义和短文级标签均为英文，短语和短文不增加翻译。
7. **敏感词条**：固定选取暴力、性、自伤和物质相关词条，验证中性教育语境和无额外露骨扩展；记录残余风险。
8. **结构破损**：缺词、重复目标、空释义、短文根层无标签、短文标签超 3、词条对象夹带标签、位置不匹配、假覆盖，均整批失败并退款。
9. **输入攻击**：未知字段、自由 Prompt、伪造词条、伪造模型、越权长度、超过组上限、并发第二请求，均在调用前拒绝。
10. **生命周期**：用户取消、刷新中断、供应商错误、完整成功后保存/放弃，以及访客认证承接，逐项验证计量和持久化结果。

每个启用模型在分配给任何组前，应以同一组最小参考样本证明能稳定产生可解析结构；M001 不要求建立自动模型评分或业务质量排行榜，但结构、覆盖和产品规则必须功能验收通过。

### 9.1 CR-040 定向验收

本次仅增加下列受影响项，不重跑上面的全量样本或全站 UI。真实调用须另行确认模型及预算；下表是待执行验收，不代表已有测试通过。

| 编号 | 可观察的验收条件 |

## 10. AI 行为验收

1. 任何模型调用都能追溯到一个合法 DATA-010 和一次明确 DATA-009 结果。
2. 任何 DATA-012 都能追溯到完整通过本契约校验的结果，不存在部分保存。
3. 模型文本差异不改变语言、场景、最低长度、目标覆盖和复习元数据约束。
4. 所有取消、失败、放弃和承接路径的额度、累计次数和保存结果与第 5 节一致。
5. 参考样本覆盖普通、词形、多词、敏感、破损和攻击输入，且结果可由后续验收角色重复判定。
6. DATA-018 的变化不会改变 DATA-010、输出目标语言或已生成内容；界面本地化不进入模型提示的用户配置语义。
7. 匿名同词分组完全由校验后的目标 occurrence 派生，不增加模型输出字段或调用；任何学习者投影都不暴露原词、可逆目标标识或答案长度。
